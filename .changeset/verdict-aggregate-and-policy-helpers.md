Add the v2 run verdict aggregator to `@mcpjam/sdk/contract`: `aggregateEvalRunVerdict` and `aggregateEvalCaseVerdict` turn iteration observations into an `EvalVerdictDecision` — validity phase first, then the task verdict, with reasons in vocabulary order — rule for rule the aggregator MCPJam's hosted and SDK-ingest finalization use, and every decision is checked against `evalVerdictDecisionSchema` before it is returned. Malformed evidence or policy throws `EvalVerdictAggregationError` with the same reason the backend gives. `evalV2TrialObservation` and `evalV2IterationHasEvaluatorError` read one iteration's evidence (lifecycle status, result, and the `metadata.scores` / `metadata.evaluationConfig` an SDK upload carries) the way the backend does, so a broken grader is an evaluator error rather than a task failure. Both are held to a run-level parity corpus generated by the backend.

Also move the tool-policy name and block helpers into the contract: `validateToolPolicyNames` (an unmatched `deny` name throws `UnmatchedToolPolicyNameError`, which now also carries the unmatched `names`; an unmatched `allow` is a warning), `TOOL_POLICY_BLOCK_MARKER` and `isToolPolicyBlockResult`. The Inspector server re-exports them unchanged.
