`parsePluginBundle` follows more of the Agent Plugins 1.0 MCP rules: a remote URL carrying user info, a fragment (even an empty one), whitespace, a backslash or a control character, or a path segment, query value or query parameter name that looks like a credential, or without exactly two slashes before its host, invalidates its server (and is never stored or repeated in an issue), header names that differ only in case invalidate their server, a `${PLUGIN_ROOT}/…` or `${PLUGIN_DATA}/…` working directory that escapes its placeholder is refused, and any `127.0.0.0/8` or `::1` host counts as loopback for plain HTTP. A malformed or non-HTTPS `homepage`, `repository` or `author.url` is now reported and not stored instead of rejecting the plugin, as the spec requires, and one carrying a credential (a user name or password, or a key in its path, query or fragment), or anything URL parsing would rewrite (a backslash, whitespace, a control character, empty user info, or other than two slashes before the host), is reported, without repeating it, and not stored; any other fragment is kept, and a long slug of words is not read as a key; a non-string `author.name` or `author.email` is rejected and unknown `author` fields are reported.
