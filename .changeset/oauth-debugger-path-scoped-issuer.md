Add opt-in support for path-scoped authorization servers to the OAuth Debugger, mirroring the toggle the XAA debugger got in #3049.

Multi-tenant authorization servers such as Scalekit scope their endpoints under a path (`https://<env>.scalekit.cloud/resources/res_x`) while their metadata advertises the origin root as `issuer`. The 2026-07-28 debug state machine enforces RFC 8414 §3.3 with an exact string comparison, so those servers hard-failed discovery with no way to proceed — the same shape the XAA debugger already had an escape hatch for.

The state machines gain an `allowPathScopedIssuer` option (`BaseOAuthStateMachineConfig`), surfaced in the inspector as a "Path-scoped authorization server" switch — in the OAuth Debugger's "Configure Server to Test" dialog and, since Connect runs the same state machine, in the Connect server form under Authentication → Advanced Settings. Both edit one per-server setting. It is **off by default**: the strict exact-match rejection still fires, and its message now names the toggle so the fix is discoverable from the error rather than only from the docs. Only the 2026-07-28 era enforces the check, so earlier protocol versions are unaffected either way.

The opt-in is threaded through every flow entry point that reaches the machine — the debugger, the initial connect, both reconnect paths (including the shared reconnect options builder used by step-up re-authorization), and the Auth tab — so the toggle cannot appear to work on one surface and silently do nothing on another. The hosted chatbox gate is deliberately excluded: its bootstrap payload does not carry the field, so wiring it client-side alone would be dead code.

The setting persists as a new top-level server field, `oauthAllowPathScopedIssuer` — deliberately separate from XAA's `xaaAllowPathScopedIssuer` so opting one debugger in never widens trust in the other. **This needs a matching `oauthAllowPathScopedIssuer` column on the `servers` table (and the `updateServer` / `createServer` mutation args) in the backend before it can be saved**: the field is only sent once it is set, but Convex rejects unknown mutation arguments, so flipping the toggle against a backend without the column fails the save. It cannot be caught at compile time — the mutation is referenced as `useMutation("servers:updateServer" as any)`.

Enabling it relaxes exactly one thing — an advertised issuer that is a same-origin path-prefix _ancestor_ of the URL discovery started from. The comparison is segment-aware (`/resources` is an ancestor of `/resources/res_x` but not of `/resources-evil`), a query or fragment on either side disqualifies the relaxation (RFC 8414 §2 forbids both in an issuer identifier), and cross-origin issuers are still rejected outright. Even under the opt-in, `token_endpoint` and `registration_endpoint` must stay on the advertised issuer's own origin — and a present-but-non-string endpoint counts as escaping rather than skipping the check: without that binding, a same-origin tenant, the exact party this feature extends trust to, could advertise the origin-root issuer to pass the prefix check while pointing the token endpoint at an arbitrary public host, redirecting the client secret and authorization code off-origin. Accepting a path-scoped issuer also emits a warning entry in the flow log, since strict MCP clients may still refuse to connect to the server being debugged.
