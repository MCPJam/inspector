SAML support for the XAA (Cross-App Access / ID-JAG) debugger, sourced to draft-ietf-oauth-identity-assertion-authz-grant-04. Two independent identity axes, everything additive:

- **Vocabulary (browser-safe):** `IDENTITY_ASSERTION_FORMATS` (`oidc` | `saml`, input axis) and `SUBJECT_IDENTIFIER_FORMATS` (`oauth-sub` | `saml-nameid`, output axis) with defaults and `normalizeIdentityAssertionFormat`/`normalizeSubjectIdentifierFormat`, exported from both the node barrel and `@mcpjam/sdk/browser`. `SAML2_TOKEN_TYPE` (`urn:ietf:params:oauth:token-type:saml2`) joins the token-type constants.
- **SAML mint + hardened validation (Node-only):** `issueMockSamlAssertion` signs a SAML 2.0 bearer assertion with the xaa-idp-1 RS256 keypair (enveloped signature, exclusive C14N, SHA-256, XML-escaped user values). `verifyMockSamlAssertion` implements a hardened contract: size cap before decode/parse, DTD/entity rejection, exactly-one structural gates, an explicit algorithm allowlist (SHA-1 rejected), pinned-key signature verification with a reference-URI-to-Assertion-ID bind, and claims parsed exclusively from the cryptographically verified `getSignedReferences()` content — never the pre-verification DOM. `decodeSamlAssertionSubjectUnsafe` covers the forgiving mint route with the same size/DTD guards.
- **`sub_id` (draft §3.2.2):** `IssueIdJagParams.subjectId` mints a `saml-nameid` `sub_id` claim derived from the IdP issuer and the target RAS entity ID — never copied from the subject token's own NameID/audience. The `unknown_sub` and `missing_claims` negative modes now tamper/remove every subject-resolution hint (`sub`, `sub_id.nameid`, `email`) together so SAML-resolving authorization servers can't silently pass a broken probe.
- **Shared handler cores:** `/authenticate` mints SAML assertions on `assertionFormat: "saml"` (OIDC response unchanged), the RFC 8693 grant accepts SAML 2.0 subject tokens with strict verification plus a `subject_id_format` mock-extension param, and the JSON exchange decodes SAML input and mints `sub_id` on request — both axes independently selectable.
- **Flow engine:** `identityAssertionFormat`/`subjectIdentifierFormat` on the XAA state-machine config and flow state (sticky, reset like `negativeTestMode`), SAML-aware `authenticateUser`/`exchangeIdTokenForIdJag`, new `identityAssertionSubject` state for UI display, and matching `XaaFlowConfig` options threaded through `runXaaFlow` and the in-process executor.
- **Browser-entry guard:** an esbuild import-graph test asserts the XML/DSig stack (`xml-crypto`, `@xmldom/xmldom`, `xpath`) can never reach `@mcpjam/sdk/browser`.
