Eval description-rewrite experiments get a report-only contract and a converter seam

**A description change had no document.** Rewriting a tool's description is the lever the run view wants to pull, but nothing assembled two replayed arms into one comparison a dashboard, an MCP tool, or a later backend materializer could read the same way. `@mcpjam/sdk/contract` now ships `descriptionExperimentReportSchema` and `buildDescriptionExperimentReport`: Newcombe interval in points, rewrite-arm eligibility that requires the override was applied, regression as `noDeterministicRegressions` over other cases, and a Controlled vs Reproducible label.

**Description only, at the converter.** `applyToolDescriptionOverrides` and `MCPClientManager.getToolsForAiSdk({ toolDescriptionOverrides })` rewrite `description` and leave name, schema, and `_meta` byte-identical. `HostRunner` applies the same map after visibility drop and re-applies it through `withOptions`. The platform client can propose, start, and read an experiment; HTTP routes land next.
