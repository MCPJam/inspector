A credit stop records its recovery on the run, and the v1 API returns it as `creditRecovery`, with the `resumeSelection` a resume of the run would launch. A `resumeFromRunId` launch the backend cannot resume answers 400, 404 or 409 with the `RESUME_*` reason, not a 500. A fan-out target refused for credits keeps its `recovery`, and every group launch is keyed, so replaying it with the receipt's `idempotencyKey` starts only the targets that did not start. A hosted-harness turn the model proxy refused for spend stops the run with its one step. After a credit top-up or a plan upgrade, the page tells a user an agent sent there to go back and tell it to continue.
