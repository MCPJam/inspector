Give an environment its own model, and hold a client to pinning one.

An environment now carries an optional `modelId` that OVERRIDES the model pinned on the client it selects. Absent means inherit, not "no model" — so `POST /environments/:id/resolve` answers with both: `modelId` (the stored override, when set), `effectiveModelId` (what will actually run), and `modelSource` (`"environment"` or `"host"`), which is the distinction an editor needs and could not previously make. `PATCH` takes `modelId: null` to clear the override and fall back to the client's; an empty string is rejected rather than treated as a clear, and the id is trimmed at the write boundary because it is stored and compared verbatim downstream.

Both halves of that resolution can be empty, and an environment that names no model cannot launch at all. The backend refuses it with `ENV_MODEL_REQUIRED`, which now reaches callers as a 409 carrying `details.reason: "environment_model_required"` — the same shape from the v1 resolve route and from the eval runner's launch path, so a caller branching on the slug gets one answer whichever surface refused it. Previously the runner leaked it as a bare Convex rejection that read as an internal fault.

The forward-client invariant closes the other end: a client created through `POST /hosts` must pin a model, by explicit `config` or by template, because every environment that selects it inherits that model. The check is a refinement over the passthrough config record, not a second copy of `ensureHostConfigV2` — the XOR message still wins for a degenerate `config: {}`, whose real problem is that it picked neither branch. In the client builder, clearing the model of a client that HAD one is now a blocking save error; a client that was already modelless stays a warning, so legacy rows do not strand an unrelated rename behind a model choice. Existing rows are otherwise untouched — the invariant binds new clients only.

`GET /environments/capabilities` reports `modelOverrides` and `modelMatrix` for version skew, not feature flagging: the SDK and CLI ship independently of the platform, and an unknown field is a hard validator error there rather than a silently ignored one. The CLI asks only when model input was actually supplied, so an ordinary `environments create` costs no extra round trip, and a deployment too old to answer reports `false` for everything. `mcpjam environments create/update` gain `--model` and `--clear-model`. The operation is excluded from the agent registry — it is a compatibility probe, not an action, and the write paths already ask it on the caller's behalf.

Model attribution on eval sessions is now the model that ran. The hosted runner persists the RESOLVED id — the one the `/stream` call billed — and the local runner persists `test.model` only when the case actually needs a model, on both the success and the throw path: a model-free case reaches the runner with a display-only sentinel, and labelling a session with it would name a model that never ran. The Explore table labels each case row from the iterations' own snapshots rather than the case's current authored model, so a finished environment-backed run is no longer relabelled with whatever the case would run today, and a row whose iterations span two models is marked mixed instead of picking one.

Provider classification moves to one canonical module (`shared/model-provider.ts`). The same question — given only this id, which provider serves it — was answered slightly differently in at least four places, and the divergences were real: `meta-llama/…` classified as `meta-llama` here and `meta` there, `mistralai/…` fell through to Ollama, and a bare unknown id became `openrouter` in chat but `ollama` in the runner. The module is pure and is the source of truth; the backend keeps a hand-mirrored copy (Convex cannot import from this repo) checked against the same fixture vectors, so changing one fails the other's parity test.

Swarm launch waves stop scheduling once an organization hits its credit limit. Every remaining launch would be rejected for the same reason, so the wave now costs one round trip instead of N and shows one banner instead of N identical ones. Requests already in flight are allowed to settle rather than cancelled — a launch is a POST that may already have created a durable run row, and aborting the client half would leave one running with nobody watching. The wave's `launchJourney` prop also regains `environmentIds` in its type, which a conditional spread had been hiding from excess property checking while the call site passed it.
