Swarm launches can use sponsored conversations. When the backend allocates a conversation to a signed-in user's sponsored allowance, the runner sends the platform claim on that conversation's host steps and target setup (only on the MCPJam-hosted model rail, never BYOK or a harness) and attaches the service token to its persona and grounding calls; the `swarm-sponsorship-v1` capability is advertised only when `INSPECTOR_SERVICE_TOKEN` is set. A platform capacity or sponsorship failure ends the conversation as failed with platform wording, is never retried onto a paid path, and never opens the customer upgrade dialog. An organization spend cap now stops only the credit-funded conversations of a run that also has sponsored ones. The New swarm flow shows "N sponsored conversations · M use org credits" before launch, launches each run with the count it showed, and stops for review (never auto-retrying with more paid conversations) when the split changes. Remaining sponsored conversations appear in the sidebar credits card and the organization usage card. New optional `expectedSponsored` on swarm and goal launches, typed `409 swarm_funding_changed`, and `POST /api/web/swarm/funding-preview`.
