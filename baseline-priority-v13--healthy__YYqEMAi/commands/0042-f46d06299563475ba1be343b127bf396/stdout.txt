These versions must ship after the backend run-start endpoint is deployed. Earlier versions keep their existing behavior.\n\n`mcpjam test <file>` runs an MCPJam suite file locally: it connects your MCP servers, drives each case's prompts through a model, grades the transcript with the same assertions a hosted run uses, and decides the run with the same verdict policy. Bring your own provider key and authenticate the run with MCPJam. With MCPJam-hosted inference it uses your existing CLI login and billing.\n\nResults are **never uploaded**. The command writes results to your terminal and, if you ask, to a report file. It records the run start with MCPJam. Like every command, it sends the CLI's single anonymous [telemetry](https://docs.mcpjam.com/cli/telemetry.md) event, which `--no-telemetry` or `DO_NOT_TRACK=1` turns off; the run adds no telemetry of its own.\n\n## Eval identity and local data\n\nRun `mcpjam cloud login` locally, or set `MCPJAM_API_KEY` to an organization `sk_` key in CI. The SDK also accepts `apiKey` or `mcpjamAuth` in run options. Explicit credentials take precedence over `MCPJAM_API_KEY`, which takes precedence over the saved CLI login. An invalid explicit credential never falls back to another account. CI never starts an interactive login. Ask an organization admin for a key if you cannot create one.\n\nEvery logical run needs an online start response. MCPJam retries transient failures within ten seconds, then stops before execution. A prior successful run does not enable offline execution. The CLI resolves the project using its existing `--project`, environment, and linked-project settings; a key can only access its own organization.\n\nWith results uploads disabled, the start-run request sends only the credential in the authorization header, any MCPJam API headers you configure through the SDK's `inference.resolveMcpjam`, project selection, a new run-start ID, client version and surface (SDK, CLI, or Vitest), planned iteration count, provider names, and whether a client profile is used (`unknown` for custom executors). The server resolves the organization and account. The start-run request sends no prompts, outputs, tool calls, or server URLs. MCPJam-hosted inference still sends prompts through MCPJam to the model, as before. Retries reuse the same ID. Planned iterations are intent, not completed usage or a charge. This release adds no debit, quota draw, or balance refusal.\n\n`DO_NOT_TRACK`, `MCPJAM_TELEMETRY_DISABLED`, and CLI telemetry settings disable analytics, not the required run-start request. Results remain local unless result uploading is enabled separately.\n\n## Quick start\n\n### 1. Write a suite\n\nSave this as `.mcpjam/evals/example.yaml`:\n\n```yaml theme={\"theme\":\"css-variables\"}\nschemaVersion: \"2\"\nmode: agentWorkflow\nreportingMode: standard\nsuite:\n  id: s_notes_example\n  name: Notes server\ntarget:\n  servers:\n    - name: notes\ndefaults:\n  judge:\n    enabled: false\n  model: anthropic/claude-haiku-4.5\n  iterations: 1\n  passThreshold: 1\n  validity: {}\ncases:\n  - id: c_reads_a_note\n    title: reads the note it was asked about\n    steps:\n      - id: s1\n        kind: prompt\n        prompt: What does note 7 say?\n      - id: a1\n        kind: assert\n        assertion:\n          type: toolCalledAtLeastOnce\n          toolName: read_note\n  - id: c_never_deletes\n    title: never deletes when only asked to read\n    steps:\n      - id: s1\n        kind: prompt\n        prompt: Summarize note 7.\n      - id: a1\n        kind: assert\n        assertion:\n          type: toolNeverCalled\n          toolName: delete_note\n```\n\n`mcpjam cloud eval validate --file .mcpjam/evals/example.yaml` checks the file offline, with no account.\n\n### 2. Configure the server\n\n`mcpjam test` binds each `target.servers[].name` to a local MCP config. The simplest is a `.mcp.json` next to where you run the command:\n\n```json theme={\"theme\":\"css-variables\"}\n{\n  \"mcpServers\": {\n    \"notes\": {\n      \"command\": \"node\",\n      \"args\": [\"./notes-server.js\"],\n      \"env\": { \"NOTES_DB\": \"${NOTES_DB:-./notes.db}\" }\n    }\n  }\n}\n```\n\n### 3. Supply a key and run\n\n```bash theme={\"theme\":\"css-variables\"}\nexport ANTHROPIC_API_KEY=[REDACTED]\nmcpjam test .mcpjam/evals/example.yaml\n```\n\n### 4. Fail one on purpose, then rerun it\n\nChange `toolName: read_note` to `toolName: echo` in the first case and run again: the command exits `1` and names the failing assertion. Fix it, then rerun just that case and keep a report:\n\n```bash theme={\"theme\":\"css-variables\"}\nmcpjam test .mcpjam/evals/example.yaml --case c_reads_a_note --reporter junit-xml --out reports/local.xml\n```\n\n`--case` takes the exact authored id and is repeatable.\n\n## Server bindings\n\nFor each target server name, the first source with an entry wins — the whole entry, never a field-level merge:\n\n1. `--server <name>=<url>` (repeatable; HTTP(S) only). For a suite with exactly one target, `--url` / `--command` and their auth flags bind it instead.\n2. `--mcp-config <path>` — an explicit MCP JSON config. A missing or invalid explicit file fails setup.\n3. `./.mcp.json`\n4. `./.mcpjam/mcp.json`\n\nPaths are relative to the directory you run the command in, not to the suite file. An explicit `--mcp-config` can bind some servers while the two conventional files still supply the rest. A lower-precedence file is read only while names remain unbound, and entries for servers the suite does not target are ignored — their processes are never started. Every name still unbound is reported together (exit `4`).\n\nConfig entries use the standard `mcpServers` shape (`command`/`args`/`env`/`cwd` for stdio, `url`/`headers` for HTTP, with `type`/`transport` spellings such as `stdio`, `http`, `sse`, `streamable-http`). `${VAR}` and `${VAR:-default}` are expanded in the winning entries only; an unset `${VAR}` fails setup naming the variable, never its value. Nothing is shell-expanded. A relative `cwd` (or `credentialsFile`) resolves against the config file's directory; a stdio entry with no `cwd` runs in the invocation directory.\n\nOne credential is never shared across servers: servers that need their own auth each get their own config entry.\n\n## Inference\n\n| `--inference` | Model id | Rail |\n| - | - | - |\n| `auto` (default) | `provider/model` and the provider's key is set | BYOK |\n| `auto` | `provider/model`, no key | MCPJam, when it serves the model and you are signed in |\n| `auto` or `mcpjam` | `mcpjam/provider/model` | MCPJam |\n| `byok` | `mcpjam/…` | refused — the prefix is explicit routing intent |\n| `byok` | `provider/model` | BYOK; the provider key is required |\n| `mcpjam` | `provider/model` | MCPJam; the model must be one MCPJam serves |\n\nThere is no fallback: a key the provider rejects is a credential failure (exit `3`), never a reason to spend platform credits instead.\n\nBYOK keys are read from the standard variables: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY` (or `GEMINI_API_KEY`), `DEEPSEEK_API_KEY`, `MISTRAL_API_KEY`, `OPENROUTER_API_KEY`, `XAI_API_KEY`. `ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL` and `OLLAMA_BASE_URL` point a provider at a gateway or proxy.\n\nMCPJam-hosted inference uses the Cloud credential precedence (`--api-key` > `MCPJAM_API_KEY` > `mcpjam cloud login`) and project precedence (`--project` > `MCPJAM_PROJECT` > `mcpjam cloud link` > most recently updated), plus `--api-url` / `--api-header`. The platform is contacted only when a selected case needs it. Hosted inference still makes inference and billing requests; \"no upload\" means no eval results or artifacts are ever sent.\n\n## Hosts\n\n`--host <template>` emulates one existing host template — its `initialize` identity, advertised capabilities, protocol versions and tool visibility, plus its model settings where the suite does not set them. It never launches the real client, and reports say \"emulated\". The suite's model, and any authored `systemPrompt` / `temperature`, win over the template's. `target.hosts` in the file is recorded as declared but not executed, and `target.environment` as declared but not resolved.\n\n## Reasoning effort\n\nA local suite file does **not** take a reasoning effort yet: `defaults` has no\n`reasoningEffort` key (a dialect-2 default needs a matching backend field on the\nsuite's default config, which has not shipped), so the value is rejected as an\nunknown key rather than accepted and ignored. A blocked call is not graded as a call and is not an executed tool span. A `deny` name that matches no tool the servers expose is invalid input (exit `2`); an unmatched `allow` is a warning.
