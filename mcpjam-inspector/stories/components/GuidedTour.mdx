# Guided Tour

A few stops on example data that walk someone through a workflow, then hand
off to the real control where they do it themselves. The Evaluate tour
(`components/evaluate/tour`) is built this way.

## Which one to use

| You want to                                   | Use                                                                     |
| --------------------------------------------- | ----------------------------------------------------------------------- |
| Show how a multi-step workflow fits together  | Guided tour                                                             |
| Point at one new feature the user can try now | [Feature Spotlight](?path=/docs/components-feature-spotlight--overview) |
| Explain a page that has no data yet           | Empty state                                                             |

A tour costs the user a minute, so save it for workflows with several pages
or concepts that only make sense together.

## The parts

Everything lives in `client/src/components/guided-tour`. The card is the
Feature Spotlight card from `@mcpjam/design-system/feature-spotlight`, so a
tour and a one-time spotlight always look the same. Change the card there,
not in a tour.

| Part                                | What it does                                                                                                |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `TourCoachmark`                     | A spotlight card pinned beside an anchor rect, placed `bottom`, `right` or `top` and kept inside the stage. |
| `TourStepContent`                   | The step trail, title, body, step count, Skip tour and Next (Finish on the last stop).                      |
| `TourSpotlight`                     | Dims the stage except one or more rects.                                                                    |
| `useAnchorRects`                    | Measures `data-tour-anchor` elements inside the stage, and keeps measuring as they resize.                  |
| `TourGhostCursor` + `useTourPlayer` | Plays a transition script: the cursor moves, clicks and types, and the tour swaps screens. Skip cancels it. |
| `useGuidedTour`                     | The lifecycle (`intro`, `stage`, `handoff`, `closed`), auto-open once per browser, and the funnel events.   |

## Building a tour

1. **Pick 3 to 5 stops.** One idea each, in the order the user will do them.
   Write titles as what the user gets, and keep bodies to two short sentences.
2. **Draw the stops on example data.** Mock screens copy the real pages, carry
   an "Example data" badge, and are `inert`. Put `data-tour-anchor` on what each
   stop lights.
3. **Script the moves between stops.** With `useTourPlayer`, the cursor presses
   the control that would really lead to the next page. Reduced motion skips
   the cursor and every delay.
4. **End on the real thing.** The last step opens the real page and a "Your
   turn" card pinned to the control the user should press next. Any click,
   Escape or the control going away closes it.
5. **Decide when it shows.** Auto-open once, only where the user hasn't used
   the feature yet. Offer a replay button until they have, then hide it.
6. **Wire up the funnel.** Give `useGuidedTour` a `location` and five event
   names (opened, step viewed, skipped, completed, handoff ended), registered
   in `shared/analytics-events.ts`. Then tag the feature's activation events
   (a suite created, a first run) with `after_tour` so the funnel ends in real
   usage.

## Behavior

- Escape, the corner X and Skip tour all close the tour, at any point,
  including mid-transition.
- Next takes focus on each stop, so Enter advances.
- The stage covers the page, so the real UI never shows between screens.
