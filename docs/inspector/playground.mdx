Playground shows you what your users will see. Pick an AI client to emulate, such as ChatGPT or Claude, and a model. Send a prompt, and watch the model decide which of your tools to call. Widgets render the way that client would show them, and every step is there to inspect.

## Debug a widget

Each widget has a row of tabs above it:

- **Data**: the tool's input and output.
- **Widget State**: the state a ChatGPT App widget has saved.
- **Model Context**: what an MCP App widget has told the model.
- **Sandbox**: Content Security Policy problems, under **Findings**, **Policy Diff** and **Sandbox Stack**.

Click **Edit** to change the tool's input or output and watch the widget re-render. Switch between **Inline**, **Picture in Picture** and **Fullscreen** to check each display mode.

## Run a tool without the model

In the **Tools** rail, pick a tool, fill in the form generated from its input schema, and click **Run**. The result appears in the conversation like a model's tool call, widget included. **Save request** keeps the inputs for later; **Refresh tools** reloads the list after you change your server.

## Compare clients or models

- **Clients**: open the client chip and tick **Compare with** next to up to two more clients. Each pane has its own **Pane settings** for its model and servers.
- **Models**: in the model chip, turn on **Multiple models** and pick up to three.

You can compare clients or models, not both at once.

## Match the client's environment

The toolbar above the conversation changes how the current client behaves in this chat. It doesn't change the saved client.

| Control | What it sets |
| --- | --- |
| Device | **Phone**, **Tablet**, **Desktop**, **Custom** or **Fill** |
| **Light mode** / **Dark mode** | The theme passed to widgets |
| Locale and Timezone | The values passed to widgets |
| CSP | **Permissive** or **Strict** |
| **Hover**, **Touch**, **Safe Area** | Input capabilities and screen insets |
| **Client Context** | The raw host context JSON sent to widgets |
| **Host Capabilities** | Which host capabilities widgets can use |

## Sessions

Every chat is saved under **Sessions** in the left rail. From a session you can rename, pin, share it with your project, archive it, or turn it into an eval case with **Promote to test case**.

## The composer

- The **+** menu adds a server, attaches files, and opens **System Prompt & Temperature** and **Tool Approval**.
- Type `/` to insert one of your server's prompts or a skill. See [Skills](/inspector/skills).
- Click the mic to dictate a message.

## JSON-RPC logger

**Logs** in the right rail streams every message between MCPJam and your servers: tool calls and results, `window.openai` calls from ChatGPT App widgets, widget state updates and MCP App messages such as `ui/initialize`. Click an entry to see its full JSON. You can search the log, filter it by server and level, and copy or download it.

## Elicitation

When a server needs more input partway through a tool call, Playground shows its request in a dialog and continues the call once you answer. This works for tool calls from the model and from MCP App widgets.

### Form elicitation

Fill in the fields the server asks for and click **Accept**, or click **Decline**.

### URL elicitation

The server asks you to open a URL, for example to sign in or pay. The dialog shows the full URL as text, with the host emphasized, and warns about `http://` links, look-alike hostnames, credentials in the URL and bare IP addresses. Other schemes, such as `javascript:`, are blocked.

Click **Open in new tab**. If the pop-up is blocked, use **Copy link** instead. Click **Decline** to refuse.

### URL-required notices

If a tool call fails because the server needs you to finish a step in your browser first (MCP error `-32042`), Playground shows a notice with the URL. Open it, then retry the tool call.

## Workspace tools

When you're signed in as a member of a project, the model also gets tools for working with the servers saved in that project.

| Tool | What it does |
| --- | --- |
| `list_project_servers` | Lists the project's servers with their transport and whether they're enabled. |
| `diagnose_server` | Connects to a server and reports its capabilities and any connection errors. |
| `list_server_tools` | Lists a server's tools with their descriptions and input schemas. |
| `list_server_revisions` | Lists the stored snapshots of a server's tools and info, newest first, without connecting. |
| `get_server_revision` | Reads one stored snapshot. |
| `diff_server_revisions` | Compares two snapshots: tools added, removed and changed. |
| `call_server_tool` | Runs a tool on a server with your authorization. It can have side effects. |
| `list_server_prompts` / `get_server_prompt` | Lists a server's prompts, or renders one with arguments. |
| `list_server_resources` / `read_server_resource` | Lists a server's resources, or reads one by URI. |
| `start_claude_readiness_run`, `start_openai_readiness_run`, `start_muse_readiness_run` | Grades a server against Anthropic's, OpenAI's or Meta's directory rules. |
| `get_readiness_run`, `list_readiness_runs`, `cancel_readiness_run`, `get_readiness_report` | Reads, lists or stops readiness runs, and reads a finished run's findings. |

Tools that change something, such as `call_server_tool` and the readiness runs, always ask you to approve each call. Tools that connect to one of your servers follow the client's tool approval setting. Listing tools never ask. Stdio servers aren't supported.

## Browser

In the local inspector, Playground can give the model a browser. The first time, it asks **"Let agents use your browser?"**. Click **Allow browser access**, or **Not now** to decide later from the **Browser** tab in the right rail. Each client can turn browser tools on or off in its [Browser settings](/inspector/clients#browser-settings).

Page text, screenshots and tool results the model sees may be sent to your model provider, so take care with signed-in sites.

## Good to know

- **Models and credits.** Models served by MCPJam use MCPJam credits, and some need you to sign in. Add your own provider keys in your organization's settings to use them under **Your providers**.
- **Trace and Raw are missing.** They're hidden while you compare and the chat has messages. In the hosted app, they need a model served by MCPJam or by your organization.
- **Comparing hides the toolbar.** Set each pane's model and servers in its **Pane settings** instead.
- **Browser sign-ins.** The desktop app keeps website sign-ins in a separate profile for each account and project. **Clear inspection site data** removes the current profile's website data.
