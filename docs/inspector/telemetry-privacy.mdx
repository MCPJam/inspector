MCPJam uses three telemetry services: **PostHog** for product analytics and session replay, **Sentry** for error reports, performance traces and error replays, and **Axiom** for server logs on the hosted service. This page describes what each one receives, how links that work as credentials are kept out of all of them, what this does not cover, and how to turn telemetry off.

For the command-line tool, see [CLI telemetry](/cli/telemetry).

## Privacy levels

Every browser session runs at one of three privacy levels. The level decides what session replay may record and how much detail product analytics keeps.

| Level    | Session replay                                                                                                                  | Product analytics                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `off`    | None. No recorder runs.                                                                                                          | Usage events, scrubbed as described below. On the hosted service, also masked as at `masked`. |
| `masked` | PostHog replay only: layout and interaction, with every text node and input masked, media and links blocked, and no console logs or network headers or bodies. Sentry Replay does not run at `masked`. | Element text and attributes masked. Names in URLs are replaced, ids and route words stay. |
| `full`   | PostHog replay: layout and interaction, with every text node and input masked, media and links blocked, and no console logs or network headers or bodies. Sentry Replay, with the same masking. | Usage events, scrubbed as described below                                          |

| Session                                                                                          | Level    |
| ------------------------------------------------------------------------------------------------ | -------- |
| Self-hosted with `npx` or Docker                                                                 | `off`    |
| Any build made with `VITE_DISABLE_POSTHOG_LOCAL=true`                                            | `off`    |
| Hosted, a share link to a published study                                                        | `off`    |
| An organization with session replay off is in view, or the person belongs to one                | `off`    |
| Desktop app                                                                                      | `off`    |
| Hosted, anything MCPJam cannot verify as non-private (a private organization in view, membership of one, a visitor with no session) | `off`    |
| Hosted, a context MCPJam verifies as non-private                                                 | `full`   |

The level is decided for the organizations and projects in view, and it fails closed: nothing is recorded until the level is known, and a navigation records nothing until the new page's level is known and the page has loaded.

Analytics and error reports identify a person by user id only, until MCPJam clears names for that account. Members of an organization with enterprise privacy are never named, and values sent earlier are cleared.

## What each service receives

| Service        | What it receives                                                                                                                                                                                                                                                                       |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PostHog events | Usage events with their properties: page URL, referrer, clicked links and element chains, web vitals, heatmap data, captured exceptions, person properties. Every property passes through the credential scrubber before it leaves the browser. |
| PostHog replay | At `masked` and `full`, a recording of the page as described above. For network activity, only the scrubbed URL and timing of each request. Request and response headers and bodies are never recorded, at any level.                                                                 |
| Sentry         | Error reports with stack traces and breadcrumbs, and performance traces, at every privacy level. A credential link's transaction name is its route template (`/results/:runToken`). Events, transactions, spans and breadcrumbs pass through the credential scrubber before sending. |
| Sentry Replay  | At `full` only, a replay of the session around an error, with text, inputs and media masked, links and frames blocked, and no network detail. Credentials are scrubbed from its page URLs and stylesheets before it is sent. |
| Axiom          | Log lines from the hosted service. URLs in a log line are scrubbed before it is written.                                                                                                                                                                                               |

## Links that are credentials

Some MCPJam URLs are credentials. Anyone holding the link has access, so a copy of the URL in a telemetry service is a copy of the credential.

- **Share links**: score and benchmark results (`/results/…`, `/bench/results/…`), shared conformance and eval reports, and published study tester links.
- **Handoff links** that pass a server connection from one device to another.
- **Sign-in and authorization callbacks**: the MCP OAuth callback and the sign-in callback, which carry one-time codes.
- **Secret parameters on any URL**: the query and fragment keys below, compared case-insensitively, plus a username and password embedded in a URL.
  - OAuth and OIDC: `code`, `state`, `access_token`, `refresh_token`, `id_token`, `client_secret`, `code_verifier`, `assertion`, `client_assertion`
  - MCPJam session and link tokens: `token`, `_token`, `t`, `k`
  - API keys and passwords: `api_key`, `apikey`, `key`, `password`
  - Bearer tokens and one-time passcodes: `jwt`, `auth`, `authorization`, `otp`
  - Signed URLs: `signature`, `sig`
  - SSO: `ticket`, `SAMLResponse`, `SAMLRequest`, `RelayState`
  - Any key that starts with `X-Amz-` or `X-Goog-` (presigned storage URLs), or ends in `token`, `secret`, `password`, `signature`, `apikey`, `api_key` or `credential`

The secret part is replaced with `[redacted]` wherever a URL appears: an event property, a breadcrumb, an exception message, a log line or free text, raw or percent-encoded.

### Replay never records these pages

A recording captures the address bar, the page that displays the secret and the requests that send it, and scrubbing a recording after the fact is not a guarantee. So neither PostHog nor Sentry records on:

- a share or handoff link,
- a sign-in or authorization callback page,
- any page whose URL has a secret parameter in its query string or fragment.

This holds at every privacy level. Recording stops before the app navigates onto such a page and resumes, at the session's level, after it leaves.

### Secrets leave the address bar early

- A callback's code and state are removed from the address bar before telemetry starts.
- When opening a share link fails, or a handoff link is refused, the token is removed from the address bar.
- Pages on a credential link are served with `Referrer-Policy: no-referrer`, so the link is not passed to other sites as a referrer.

### Fail closed

Anything that cannot be shown to be clean is dropped, not sent. This includes a payload that is too large, malformed or in an encoding the scrubber cannot read, and any payload where the scrubber itself fails.

## Limits

### Older desktop builds

Installed desktop apps keep the code they shipped with until they update, so a build released before the protections on this page may still send a credential URL. Updating the desktop app closes this gap.

### Not covered

- **Hosting provider request logs.** The edge and CDN in front of the hosted service keep their own request logs. The scrubbing on this page runs after the edge, so those logs are not covered by it.
- **Your content.** Tool arguments, tool results, prompts and chat messages are content, not URLs. Keeping content out of logs and error reports is handled by separate content scrubbing, not by the mechanism on this page.

## Opting out

| Setting                             | Where                                       | Effect                                                                                                                                                         |
| ----------------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DO_NOT_TRACK=1`                    | Environment of the Inspector server process | The server sends no analytics events and no error reports, ships no logs, forwards nothing through its telemetry relay, and asks PostHog for no feature flags. The pages it serves start Sentry disabled and PostHog opted out. Also accepts `true`. |
| `MCPJAM_FEATURE_FLAGS_FILE=<path>`  | Environment of the Inspector server process | Feature flags come from this JSON file of flag answers (`{"flag-key": true}`, or a variant name) instead of PostHog. Use an absolute path: a relative one is resolved from the server's working directory. The server reads the file at startup and reports a missing or malformed one on stderr. Without the file, `DO_NOT_TRACK` turns every flag off, so features behind a flag are unavailable. |
| `MCPJAM_TELEMETRY_DISABLED=1`       | Environment of the desktop app process      | The desktop app sends no error reports. Also accepts `true`.                                                                                                   |
| `VITE_DISABLE_POSTHOG_LOCAL=true`   | When building the Inspector from source     | The browser sends no analytics events, records no replay and reports no exceptions. Set at runtime, it also turns off the server's analytics events.            |

`npx` and Docker installs already record no replay and report no browser exceptions. The browser bundle published to npm still sends usage events, scrubbed as above, unless the server that serves it sets `DO_NOT_TRACK`.

```bash
DO_NOT_TRACK=1 npx @mcpjam/inspector@latest
```
