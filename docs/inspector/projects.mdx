A project saves a set of MCP servers and their configuration. Share it, and everyone on your team connects to the same servers with the same settings, and sees each other's changes as they happen.

## Getting Started

The switcher at the top of the sidebar shows your active organization on the first line and your active project beneath it.

1. Click the switcher.
2. Click **Create project** at the bottom of the list, give the project a name, and choose its organization.
3. Add your MCP servers on the Connect tab. See [Connecting servers](/inspector/connecting-servers).
4. Share the project with your team. See [How to Share a Project](#how-to-share-a-project).

When you switch projects, every server disconnects, so you start clean.

## Switching Organizations

The switcher opens on the projects in your active organization, with the organization's name at the top of the list.

- To switch organizations, click the organization's name. Pick one from the list, and the sidebar reloads with its projects.
- To go back without switching, click the **Organizations** header.
- To create an organization, click **New organization** at the bottom of the list, if you can create another.

Organization settings are in **Settings**, not in the switcher.

## Creating and deleting projects

### Creating a project

Click **Create project** at the bottom of the switcher's projects view. A dialog opens with:

- **Name**: prefilled with an unused name, such as "Project 3".
- **Organization**: the organization the project belongs to. Only organizations where you can create projects are listed.

Click **Create** or press Enter. MCPJam creates the project and switches to it.

### Deleting a project

Hover a project in the switcher and click its trash icon, then click **Delete** to confirm.

<Warning>
Deleting a project is irreversible. All servers, sessions, and eval suites in the project are removed.
</Warning>

## Credits

The credits meter in the sidebar footer shows your organization's credit usage. Click it for the full breakdown, your plan and when credits reset. At 10% or less remaining, the meter turns red and shows **Low credits**.

## Leaving an organization

If you're a member, not an owner or admin, opening the organization settings shows **Access restricted**. To leave the organization from there:

1. Click **Leave organization**.
2. Confirm in the dialog.

You lose access immediately. To rejoin, an admin or owner has to invite you again.

<Note>
Owners can't leave an organization. Transfer ownership or delete the organization instead.
</Note>

## Sharing Projects

Set up a project once and invite your team by email. Everyone gets the same servers with the same configuration.

### What Gets Shared

Members get every server in the project with the same configuration. Per-server overrides, such as headers, timeout and protocol version, apply to every client in the project.

<Note>
Authorization headers and OAuth tokens are never shared. Each member signs in with their own credentials.
</Note>

## Secret storage for env vars and headers

When you save a server's environment variables (stdio) or custom HTTP headers, MCPJam stores the values as encrypted secrets. In the server's edit form, each row shows its name with the value masked.

### Viewing a saved value

Click the eye icon on a row to reveal its value, and click it again to hide it. Only that row is revealed. A value reaches your browser only when you click its eye.

<Warning>
To change the authentication type of an HTTP server with hidden headers, for example away from Bearer Token, reveal the header rows first. Otherwise saving shows an error, so you don't overwrite headers you can't see.
</Warning>

### How updates work

- Environment variables: any edit to the section, whether you add, remove or change a value, replaces all stored values on save.
- Custom headers: any edit to the headers or the authentication type replaces all stored headers on save.
- If you save without revealing or editing a section, its stored values stay as they are.

### Changing a server's destination

Two edits clear a server's stored credentials: changing an HTTP server's origin, or changing a stdio server's command.

- **HTTP servers.** Changing the path of the URL, such as `/mcp` to `/mcp/v2`, keeps credentials. Changing the origin (scheme, host or port) clears every credential saved for the server: headers, environment variables, the bearer token, and any OAuth access token, refresh token and client secret.
- **Stdio servers.** Changing the command or its arguments clears the server's stored environment variables.

Before either change, the edit form shows the old and new values, and you have to check an acknowledgement box to save. This includes credentials other members added that you may not see. After the save, each member who had credentials for the server has to enter them again.

### Destination history

The **Destination history** section in the server's details shows every change to its origin, command or transport, who made it, and whether credentials were cleared. Every project member can see it, on any plan.

### Real-Time Sync

New servers and configuration changes appear for every project member as soon as they're saved.

### How to Share a Project

1. Sign in to MCPJam.
2. Click the member avatars in the header, or the share button.
3. Enter the email address of the person you want to invite.
4. Click **Invite**.

When they sign in with that email address, the project appears in their project list.

### Managing Members

If you created the project, remove a member by clicking the X next to their name. Anyone else can leave the project at any time.

## Project Settings

Open the project's settings with the gear icon in the header.

### Default host config

The default host config is the starting configuration for new scenarios, eval suites and chat tabs in the project: the default model, system prompt, temperature, tool approval, connection settings, capabilities and host context.

Editing it doesn't change existing scenarios or eval suites; each keeps its own config once created. Members who can't manage the project see it read-only.

## Good to know

- **Auto-connect is personal.** The **Auto-connect** switch in the Connect header, on by default, connects every project server for you in your browser. Flipping it doesn't change the project for anyone else.
- **Unpaid seats.** If you were invited to an organization but your seat isn't paid yet, the organization appears greyed out with a **Seat not paid yet** tooltip, and isn't offered when you create a project. You can open it once the owner pays for your seat.
