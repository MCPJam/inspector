Connect your MCP server to MCPJam to test it. MCPJam connects over **STDIO** or **Streamable HTTP**, handles OAuth for you, and can keep several servers connected to a project at once.

To add a server, open **Servers** in the sidebar, click **Add Server** and pick a transport.

## STDIO servers

Enter the command that starts your server. For a Node server, that might be:

```bash
node /path/to/your/server.js
```

<Info>
  Use absolute paths, such as `/Users/yourname/project/server.py`, so the path resolves no matter where MCPJam runs from.
</Info>

### Environment variables

To pass values such as API tokens to your server, click **Add variable** in the environment variables section.

## HTTP servers

Select **HTTP** in the transport dropdown and paste your server's URL, which usually ends in `/mcp`.

### Custom headers

Expand **Custom Headers** to add headers, such as proxy auth or a tenant ID, to every request to the server.

### Authentication

Choose how MCPJam authenticates to your server:

- **No Authentication**
- **Bearer Token**: you already have an API token and don't need to register an OAuth client.
- **OAuth**: MCPJam gets a token by following [MCP Authorization](https://modelcontextprotocol.io/specification/draft/basic/authorization), with Dynamic Client Registration (DCR), a pre-registered client or a Client ID Metadata Document (CIMD). You can set scopes, or a custom client ID and secret. To step through the flow, use the [OAuth Debugger](/inspector/guided-oauth).

### Request timeout

Expand **Connection overrides** to change the request timeout from its default of `10000` ms. Raise it for slow or cold-start servers.

## Manage connections

Your connected servers are listed on the **Servers** tab.

    width="300"
  />
</Frame>

- Use a server's toggle to turn it on or off.
- Open a server's ⋮ menu to reconnect, configure or disconnect it.
- Choose **Configure** to open the server's details, with tabs such as **Config**, **Overview**, **Tools**, **Settings**, **Auth**, **Clients** and **History**.

### Server information

Each server card shows the server's icon and version, if the server provides them, its transport, and its connection status: connected, connecting, or failed with a retry count.

The server's details show:

- **Metadata**: name, title, version, protocol version and transport type
- **Capabilities**: the tools, prompts and resources the server supports
- **Instructions**: the instructions the server gives to models
- **Raw capabilities**: the full JSON of server and client capabilities, with a copy button
- **Documentation**: a link to the server's docs, if it has one

Servers that provide OpenAI Apps SDK metadata show an OpenAI logo. Their **Tools** tab lists each tool's read/write permissions and widget configuration.

### History tab

The **History** tab shows what changed in your server over time. Each row is a revision, with its number, how many tools it added or removed, and when it was recorded.

Click a revision to expand it, then switch between **Diff** and **Snapshot**:

- **Diff** lists the tools added, removed or changed since the previous revision. A changed tool shows a git-style diff of each changed field: description words highlighted, and schemas and annotations as JSON. Server info changes, such as the version or instructions, show old and new values.
- **Snapshot** lists every tool at that revision, with its name and description. Revision 1 has nothing to compare against, so it opens here.

Scripts and agents can read the same revisions without connecting to the server, so this works for stdio servers too:

- The [API](/reference/public-api#endpoints): `GET /projects/{projectId}/servers/{serverId}/revisions`, with each revision and its diff under that path.
- The [CLI](/cli/reference#cloud-projects-servers-revisions): `cloud projects servers revisions`, `revision` and `revision-diff`.
- The hosted MCP server and Playground chat: the `list_server_revisions`, `get_server_revision` and `diff_server_revisions` tools.

### Multiple OAuth accounts

You can connect more than one account to a personal OAuth server. The server's **Config** tab lists them under **Connected accounts**.

Each row shows the account's email address (or name) on the first line, and a caption on the second line: the name you gave it, plus **Default** when chat uses that account, or **Needs reconnect** when the tokens are expired or revoked.

Open the row menu (⋯) to act on an account:

- **Rename**: opens an inline field to give the account a name. The name appears in chat when the model picks an account.
- **Set as default**: promotes the row to the default. The default account is used by non-chat consumers and as the fallback when no account is specified. This option is hidden on the row that is already the default.
- **Reconnect**: re-runs the OAuth flow for that row, replacing only that credential.
- **Remove**: deletes the credential. If the removed row was the default, the next available account becomes the default.

To add another account, click **Connect another account** at the bottom of the list. A server can have up to 8.

With two or more accounts connected, chat adds a required `link_id` argument so you or the model can pick the account for each tool call. ChatGPT uses the same name, so avoid `link_id` as an argument name in your own tools. If a tool already declares `link_id`, chat shows one copy of the tool per account instead.

## Tunneling

A tunnel gives a local MCP server a public HTTPS URL, so you can try it in a client such as ChatGPT without deploying it.

Each tunnel serves one server. Its URL contains a secret key (`?k=…`), and requests without the right key are rejected with a 401 before they reach your machine.

### Create a tunnel

1. Go to the **Servers** tab.
2. Click **Create tunnel** on the server card you want to expose.
3. Copy the tunnel URL from the server card and paste it into your MCP client (for example, ChatGPT's custom connector settings).

The tunnel's domain stays the same across sessions. If you close and recreate a tunnel for the same server, you get the same domain with a new secret key.

### Rotate the secret

If someone who shouldn't have access has the URL, click the rotate button (refresh icon) on the tunnel pill. You get a new secret key on the same domain, and the old URL stops working immediately.

### Recent requests

Click the log icon on the tunnel pill to see the last 20 JSON-RPC method calls that came through the tunnel. The list refreshes every 4 seconds.

### Close a tunnel

Click **×** on the tunnel pill to stop remote access. The tunnel closes and every remote connection drops immediately. The next tunnel for this server reuses the domain.

<Warning>
  Anyone with the full tunnel URL, including its secret key, can access this
  server. Share it carefully, rotate it if it leaks, and close the tunnel when
  you are done.
</Warning>

## Good to know

- **Hosted app.** The [hosted app](https://app.mcpjam.com) connects only over HTTPS. For STDIO or plain HTTP, use the [local inspector](/installation). See [Hosted App](/hosted/overview).
- **SSE servers.** If Streamable HTTP fails, MCPJam falls back to the older SSE transport. It tries SSE first when the URL ends in `/sse`.
- **Changing the default account mid-chat.** Tool calls already in flight keep the account they started with.
- **Rerunning an account-specific call.** You can't rerun a tool call from the trace view if it ran on a specific account, because the rerun would use the default account.
