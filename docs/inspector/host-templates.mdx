MCPJam ships built-in host presets for Claude, ChatGPT, Cursor, Copilot, Codex, and MCPJam itself. Each preset captures a client's identity, capabilities, appearance, and sandbox policy so you can test widgets under that host in the [Playground](/inspector/playground).

If your MCP client is missing, or its existing preset is out of date, [open a GitHub issue](https://github.com/MCPJam/inspector/issues/new) with the client details below. The MCPJam team will review your captures and handle adding or updating the preset.

<Note>
  You do not need to write code or open a pull request. Your contribution is the
  client's details and supporting evidence, submitted to the team through a GitHub
  issue.
</Note>

## What to submit

Include these details in your issue:

- **Client identity** — product name, website, version, platform, and whether this is a new preset or an update to an existing one.
- **Protocol and capabilities** — supported MCP protocol versions, whether the client renders MCP Apps or OpenAI Apps SDK widgets, and the capabilities it advertises.
- **Initialization captures** — the MCP `initialize` exchange and, if the client renders MCP Apps, the `ui/initialize` exchange.
- **Sandbox behavior** — iframe `sandbox` and `allow` attributes, response `Content-Security-Policy` headers, and any observed restrictions on storage, links, or permissions.
- **Appearance** — a logo or link to an official asset, screenshots, and any published design tokens or fonts used by widgets.
- **Evidence and gaps** — capture dates, links to official documentation, known limitations, and anything you could not verify.

## Capture values from the real client

The most important rule is to **capture values from a live client rather than inventing them**. A preset that advertises unsupported behavior can make a widget pass in MCPJam but fail in the real client.

<Steps>
  <Step title="Capture initialization and sandbox details">
    Record as much as you can from the client:

    - **MCP `initialize` request** — `clientInfo`, the requested `protocolVersion`, and advertised client `capabilities`, including extensions and experimental capabilities. Include the response to show the negotiated protocol version and server capabilities.
    - **`ui/initialize` response** — `hostInfo`, `hostCapabilities`, and `hostContext`, including theme, display modes, container dimensions, locale, time zone, platform, device capabilities, safe-area insets, and styles.
    - **Outer iframe** — the complete `sandbox` and `allow` attributes, plus the response `Content-Security-Policy` header.
    - **Inner iframe**, if the client nests frames — the same attributes and header, captured separately.

    DevTools → Network → Response Headers and JSON-RPC logs are useful capture surfaces. Record the client version, platform, and capture date so the team can tell which behavior the evidence describes.

    If the client does not render widgets, say so and omit the UI-specific captures.

    <Warning>
      Remove credentials, tokens, cookies, private URLs, and user data before
      attaching logs or screenshots to a public issue.
    </Warning>

  </Step>

  <Step title="Open a GitHub issue with the client details">
    [Open an issue in MCPJam/inspector](https://github.com/MCPJam/inspector/issues/new) titled **Host preset: YourClient**. Include the details from [What to submit](#what-to-submit), attach your sanitized captures and logo, and link each reported behavior to a capture or official source.

    Mark unverified fields as **unknown** and explain what you could not capture. If a value is an assumption, label it explicitly instead of presenting it as measured behavior. You can submit an issue even if the captures are incomplete.

    The MCPJam team will review the evidence, follow up on missing details, and handle the preset integration. The GitHub issue is the place to coordinate that work.

  </Step>

  <Step title="Validate the preset with the team">
    Once the team makes the preset available, try a widget under it in the [Playground](/inspector/playground) and report any differences in the issue:

    - Does the preset show the right client name and logo?
    - Does `app.getHostContext()` report the expected theme and dimensions?
    - Does a widget that checks the host identity behave as it does in your client?
    - Do sandbox restrictions and CSP violations match the real client?

    Include screenshots or a small reproduction for mismatches. Call out any behavior that could let a widget pass in MCPJam but fail in your client.

  </Step>
</Steps>

## Capture checklist

| Detail | What to record | Common mistake |
| --- | --- | --- |
| `clientInfo.name` | The exact value from the client's MCP `initialize` request. | Substituting a friendly product name for the protocol identity. |
| `hostInfo.name` | The exact value from the `ui/initialize` response. | Reusing `clientInfo.name`; these identify different protocol layers. |
| Capabilities | Both advertised capabilities and any observed behavior that differs from them. | Reporting a capability as supported without checking that it works. |
| CSP | The complete response header for each frame, with its source and capture date. | Replacing the captured policy with a guessed allowlist. |
| Iframe sandbox | The complete `sandbox` attribute for each frame, including whether `allow-same-origin` is absent. | Assuming the outer and inner frames use the same policy, or omitting an opaque-origin restriction. |
| Permissions | Both the iframe `allow` attribute and the permissions advertised in `hostCapabilities`. | Assuming an advertised permission is also granted by the iframe. |
| Container dimensions | The dimensions reported by the host, separately from the measured iframe size. | Treating the host's layout intent as a literal viewport size. |

## Keep an existing preset accurate

When your client ships a new capability, changes its sandbox policy, or otherwise differs from its preset, [open a GitHub issue](https://github.com/MCPJam/inspector/issues/new) with the client name, new version, what changed, and fresh captures. Link any earlier contribution issue for context. The MCPJam team handles preset updates through the same process.
