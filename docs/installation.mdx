### Add MCPJam to your coding agent

Your agent can test MCP servers with MCPJam without opening the Inspector. Pick by what the agent should do:

- **Run MCPJam commands**
  - Install the MCPJam skill. It teaches an agent with a shell every `mcpjam` command and when to use it.
  - See [CLI overview](/cli/overview#recommended-use-with-agent-skills).
- **Test a server from inside the agent**
  - Add `mcpjam mcp`, a local STDIO MCP server. It connects to your server under test, calls its tools and keeps the session open to watch notifications. No account needed.
  - See [MCPJam as an MCP server](/cli/mcp-server).
- **Work with your MCPJam account**
  - Add the remote MCPJam MCP server for your projects, saved servers and evals. Sign in with OAuth.
  - See [MCPJam MCP server](/hosted/mcp-server).

<Tabs>
  <Tab title="Claude Code">
    ```bash Skill
    npx skills add mcpjam/inspector --skill mcp-inspector
    ```

    ```bash Local MCP server
    claude mcp add mcpjam-local -- npx -y @mcpjam/cli@latest mcp
    ```

    ```bash Account MCP server
    claude mcp add --transport http mcpjam https://mcp.mcpjam.com/mcp
    ```

    After adding the account server, run `/mcp`, choose `mcpjam`, and sign in.
  </Tab>
  <Tab title="Codex">
    ```bash Skill
    npx skills add mcpjam/inspector --skill mcp-inspector
    ```

    ```bash Local MCP server
    codex mcp add mcpjam-local -- npx -y @mcpjam/cli@latest mcp
    ```

    ```bash Account MCP server
    codex mcp add mcpjam --url https://mcp.mcpjam.com/mcp
    ```

    Codex starts OAuth sign-in for the account server in your browser; if it does not, run `codex mcp login mcpjam`.
  </Tab>
  <Tab title="Cursor">
    ```bash Skill
    npx skills add mcpjam/inspector --skill mcp-inspector
    ```

    Add the local server to `.cursor/mcp.json` in your project, or `~/.cursor/mcp.json`:

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "mcpjam": {
          "command": "npx",
          "args": ["-y", "@mcpjam/cli@latest", "mcp"]
        }
      }
    }
    ```
  </Tab>
</Tabs>

To give the agent MCPJam's documentation as well, add `https://docs.mcpjam.com/mcp`. See [MCP Docs Server](/inspector/docs-server).

### Which one do I need?

| Capability | Web App | Desktop | Terminal (`npx`) | Docker |
| --- | :---: | :---: | :---: | :---: |
| Install required | None | Mac/Windows download | Node.js | Docker |
| HTTPS MCP servers | ✓ | ✓ | ✓ | ✓ |
| HTTP MCP servers | No | ✓ | ✓ | ✓ |
| Local STDIO servers | No | ✓ | ✓ | Inside the container |
| Skills | No | ✓ | ✓ | ✓ |
| Shareable server URLs | ✓ | No | No | No |
| Always on latest version | ✓ | Updates itself | Per-run (`@latest`) | Re-pull to update |

If your server runs on `localhost`, the web app can't reach it: use the desktop app or the terminal, or Docker with `host.docker.internal`. If you want teammates to open the same server in one click, use the web app.

### Web app

Open [app.mcpjam.com](https://app.mcpjam.com). The web app accepts HTTPS server URLs only; for HTTP or local STDIO servers, use the desktop app or the terminal. See [Hosted App](/hosted/overview).

### Desktop app

Download the installer for your OS and run it:

- [Mac](https://github.com/MCPJam/inspector/releases/latest/download/MCPJam.Inspector.dmg)
- [Windows](https://github.com/MCPJam/inspector/releases/latest/download/MCPJam-Inspector-Setup.exe)

It connects to HTTP/S and local STDIO servers, and doesn't need Node.js.

### Terminal

Run the command in your terminal:

<CodeGroup>
```bash npm
npx @mcpjam/inspector@latest
```

```bash pnpm
pnpm dlx @mcpjam/inspector@latest
```

```bash yarn
yarn dlx @mcpjam/inspector@latest
```

```bash bun
bunx @mcpjam/inspector@latest
```
</CodeGroup>

The command prints a `localhost` link. Open it to use the Inspector.

<Info>
  The first time it starts, the Inspector downloads the Chromium browser it uses to render widgets, and the terminal shows the progress. You don't need to run `playwright install`. If the download fails, the browser pane shows why and retries three times on its own; after that, click **Retry now**.
</Info>

#### From your editor (VS Code, Cursor, Windsurf)

You don't need an editor extension. Run `npx @mcpjam/inspector@latest` in your editor's integrated terminal and click the printed `localhost` link.

To start the Inspector whenever your project's `dev` script starts your server, see [Launch from Code](/inspector/launch-from-code).

### Docker

Pull the image from Docker Hub and run it bound to localhost for security:

```bash
docker pull mcpjam/mcp-inspector
docker run -p 127.0.0.1:6274:6274 mcpjam/mcp-inspector
```

Open the private link printed in the container logs. Keep `-p 127.0.0.1:6274:6274` so only your machine can reach the Inspector. If you open the plain address instead, it shows how to use the link; pasting the link into an open tab signs you in without a reload.

<Warning>
**Reaching the app and your host from Docker:**

- On macOS/Windows, access the app via `http://127.0.0.1:6274` (not `localhost`)
- When connecting to MCP servers on your host machine, use `http://host.docker.internal:PORT` instead of `http://127.0.0.1:PORT`
- On Linux, `host.docker.internal` resolves only if you pass `--add-host=host.docker.internal:host-gateway` to `docker run`; `mcpjam-inspector/compose.yaml` already sets it

Example:

```bash
# Your MCP server runs on host at: http://127.0.0.1:8080/mcp
# In Docker, configure it as: http://host.docker.internal:8080/mcp
```

</Warning>

#### Accessing over the network

A native (`npx`) install binds to localhost. To reach one on another machine, use SSH forwarding (`ssh -L 6274:127.0.0.1:6274 user@host`), then open its terminal link at your forwarded address. Keep the `#token=…` part of the link. Forwarding needs only SSH access to the host and keeps the inspector port off the network, so prefer it when you only need to reach the install from your own machine.

For direct LAN access, the Docker image binds `0.0.0.0` inside the container. Set `MCPJAM_ALLOWED_HOSTS` to the address you use and publish the port on the host address that clients will connect to:

```bash
docker run -p 192.168.1.50:6274:6274 -e MCPJAM_ALLOWED_HOSTS=192.168.1.50 mcpjam/mcp-inspector
```

A bare `-p 6274:6274` publishes the port on every host interface, IPv4 and IPv6. Anything that can route to a published address can reach the inspector, so publish it only on a network you trust and only for as long as you need it. On Linux, Docker writes its own firewall rules for published ports, so ufw and firewalld rules do not block them.

Open the printed Network link, or paste the terminal link into the access screen. Allowlisting a host accepts it as a request origin; it does not grant access without the link. Cross-tab continuation works only when both tabs use the same host and port.

For a remapped port, keep the link's `#token=…` part and change the address. Set `MCPJAM_INSPECTOR_FRONTEND_URL=http://devbox.local:8080` to print a fixed address. For IPv6, bracket the allowlist entry: `MCPJAM_ALLOWED_HOSTS=[fd00::50]`. Comma-separate multiple hosts. Wildcards additionally require `MCPJAM_ALLOW_WILDCARD_ORIGINS=true` for request origins.

A restart generates a new link. To keep one across restarts, set `MCPJAM_SESSION_TOKEN` to a strong random URL-safe secret of at least 24 characters. Update `@mcpjam/cli` whenever you update the Inspector.

<Warning>
Keep access links private: they grant control of the local Inspector and its connected tools. Set `MCPJAM_LOCAL_COMPUTER_ENABLED=false` and `MCPJAM_LOCAL_BROWSER_ENABLED=false` if you do not need the local shell and browser tools.
</Warning>

#### Docker with Arguments

You can pass command-line arguments to the Docker container:

```bash
# Launch with STDIO server
docker run -p 127.0.0.1:6274:6274 mcpjam/mcp-inspector -- \
  npx -y @modelcontextprotocol/server-everything

# Launch with HTTP server
docker run --rm -p 127.0.0.1:6274:6274 \
  --add-host=host.docker.internal:host-gateway \
  mcpjam/mcp-inspector -- \
  --url http://host.docker.internal:8080/mcp \
  --name "HTTP Server" \
  --tab tools
```

STDIO servers run inside the container, not on your machine. The image includes Node.js and `npx`, but not Python or `uv`, and it can't see files on your machine. To test a STDIO server that needs those, use [Terminal](#terminal) or the [Desktop app](#desktop-app), or run the server over HTTP on your machine and connect to it through `host.docker.internal`.

See [Launch from Code](/inspector/launch-from-code).

### Start with STDIO server

Put your server's start command after the Inspector command to open the Inspector already connected to it.

<Tabs>
  <Tab title="Python Server">
    ```bash
    # Starts MCPJam inspector with a FastMCP server
    npx @mcpjam/inspector@latest uv run fastmcp run /path/to/your/server.py
    ```

    This command assumes [`uv`](https://docs.astral.sh/uv/) is installed and on your PATH. If you see `Unknown command: uv` (fish), `command not found: uv` (bash/zsh), or `'uv' is not recognized` (Windows), install it first:

    ```bash
    curl -LsSf https://astral.sh/uv/install.sh | sh
    ```
  </Tab>
  
  <Tab title="Node.js Server">
    ```bash
    # NPX package
    npx @mcpjam/inspector@latest npx -y your-mcp-package

    # Direct Node.js execution
    npx @mcpjam/inspector@latest node /path/to/your/server.js
    ```

  </Tab>
</Tabs>

<Info>
  **Use Absolute Paths**: Always use absolute file paths (e.g.,
  `/Users/yourname/project/server.py`) to avoid path resolution issues.
</Info>

### Start with custom port

The default port is `6274`. To use another:

```bash
npx @mcpjam/inspector@latest --port 4000
```

The port must be an integer from 1 to 65535; any other value exits with an error.

### Start with Ollama

Install Ollama, then pass a model name to open the Inspector and start that model with the `ollama serve <model>` command.

```bash
npx @mcpjam/inspector@latest --ollama llama3.2
```

### Start with Configuration File

Use a configuration file to connect to several MCP servers at once:

```bash
# Using npx directly
npx @mcpjam/inspector@latest --config path/to/config.json --server myserver

# If running from the repository
npm run build
npm start -- --config path/to/config.json --server myserver
```

<Info>
  **Note**: When using `npm start`, you need the `--` separator to pass
  arguments to the underlying script.
</Info>

Every server in the config is added to your project and connects on launch.
Pass `--server <name>` to connect only that one. If you're not signed in,
MCPJam asks you to sign in and then brings you back.

Example configuration file structure:

```json config.json
{
  "mcpServers": {
    "everything": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-everything"],
      "env": {
        "HELLO": "Hello MCP!"
      }
    },
    "weather-server": {
      "command": "python",
      "args": ["weather_server.py"],
      "env": {
        "WEATHER_API_KEY": "your-api-key"
      }
    }
  }
}
```

The config file can use any of these three shapes, so you can paste a config from any of these tools without reformatting:

| Shape | Example |
|-------|---------|
| `mcpServers` wrapper (MCPJam / Claude Desktop style) | `{ "mcpServers": { "my-server": { ... } } }` |
| `mcp_servers` wrapper (OpenAI plugin style) | `{ "mcp_servers": { "my-server": { ... } } }` |
| Direct server map (OpenAI `.mcp.json` style) | `{ "my-server": { ... } }` |

Declaring both `mcp_servers` and `mcpServers` in the same file is an error. A bare single-server object (top-level `command` or `url` string) is not accepted; wrap it in one of the shapes above.

#### Mixing STDIO and HTTP/SHTTP servers

You can mix STDIO and HTTP (Streamable HTTP / SHTTP) server entries in the same config. Each entry's transport is inferred from its fields: `command` + `args` means STDIO, `url` means HTTP/SHTTP.

```json config.json
{
  "mcpServers": {
    "local-everything": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-everything"],
      "env": {
        "HELLO": "Hello MCP!"
      }
    },
    "hosted-weather": {
      "url": "https://weather.example.com/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN_HERE"
      }
    }
  }
}
```

The terminal and desktop installs accept both shapes in the same file. The hosted web app accepts HTTP/SHTTP entries only; STDIO entries are ignored because the hosted runtime cannot spawn local processes.

For per-server `Authorization` headers, see [API keys → Playground BYOK](/reference/api-keys#playground-byok-not-an-mcpjam-key).

### Start with Verbose Logging

To troubleshoot a connection, log every HTTP request the Inspector makes:

```bash
npx @mcpjam/inspector@latest --verbose
```

Or use the short form:

```bash
npx @mcpjam/inspector@latest -v
```

## FAQ

<AccordionGroup>
  <Accordion title="Does MCPJam need a database?" icon="database">
    No. MCPJam Inspector runs as a hosted web app, a desktop app, or via `npx`; none of them require you to install or configure a database. Accounts, sharing, and OAuth token storage on [app.mcpjam.com](https://app.mcpjam.com) are handled by the hosted backend; the Terminal and Desktop apps store config locally on disk.
  </Accordion>
  <Accordion title="How do I check which version of Inspector I'm running?" icon="tag">
    All three installs (Web, Desktop, Terminal) show the running version in the **Settings** tab under **About MCPJam**.

    To check that an `@latest` run moved you forward, compare it with the latest version on npm:

    ```bash
    npm view @mcpjam/inspector version
    ```

    The Desktop and Web apps update on their own. For the Terminal install, the `@latest` tag in `npx @mcpjam/inspector@latest` pulls the most recent release every run.
  </Accordion>
  <Accordion title="Can MCPJam auto-install MCP servers into my repo?" icon="package">
    Not directly. MCPJam doesn't reach into your repo. The closest workflow is **Skills**: install the MCPJam CLI skill into a project so an agent working in that repo knows how to use MCP tools and call MCPJam against your servers. See [Skills](/inspector/skills).
  </Accordion>
  <Accordion title="Where are my files saved?" icon="folder">
    - **OAuth credentials** from `mcpjam oauth login`: printed to stdout, and saved to a file only when you pass `--credentials-out <path>`. See [CLI OAuth login](/cli/oauth-login).
    - **Eval results**: uploaded to your MCPJam project when `MCPJAM_API_KEY` is set to an MCPJam API key (`sk_…`). See [Saving Results](/sdk/concepts/saving-results).
    - **Inspector settings**: the hosted app keeps servers in your project; Terminal and Desktop store config locally on disk. Client edits are saved when you click **Save client**.
  </Accordion>
</AccordionGroup>
