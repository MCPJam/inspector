MCPJam offers five interfaces for testing your MCP server. For what each interface supports, see the [comparison table](/#comparison).

| Interface | Best for | MCP servers supported |
| --- | --- | --- |
| [MCPJam Inspector](#mcpjam-inspector) | Testing and debugging by hand in a visual app. | HTTPS in the web app. HTTP, HTTPS, and local STDIO everywhere else. |
| [CLI](#cli) | Running checks from your shell or CI. | HTTP, HTTPS, and local STDIO. |
| [SDK](#sdk) | Writing tests in TypeScript. | HTTP, HTTPS, and local STDIO. |
| [API](#api) | Calling MCPJam from your own code over HTTP. | Servers saved in your MCPJam projects. |
| [MCP server](#mcp-server) | Accessing MCPJam through a chat-based AI agent or interface. | Hosted: Servers saved in your MCPJam projects. Local: HTTP, HTTPS, and local STDIO. |

## MCPJam Inspector

The Inspector is a visual app for testing and debugging an MCP server by hand. To see which capabilities the Inspector app supports across different interfaces, see [Installation](/installation#which-one-do-i-need).

<Steps>
  <Step title="Open the Inspector">
    <CardGroup cols={2}>
      <Card title="Web app" icon="globe" href="https://app.mcpjam.com">
        No install. Connects to HTTPS servers. Share servers with your team.
      </Card>
      <Card title="Desktop app" icon="monitor" href="/installation#desktop-app">
        Download for Mac or Windows. Connects to HTTP, HTTPS, and local STDIO servers.
      </Card>
      <Card title="Local Inspector" icon="terminal" href="/installation#local-inspector">
        Run `npx @mcpjam/inspector@latest`. Requires Node.js. Connects to HTTP, HTTPS, and local STDIO servers.
      </Card>
      <Card title="Docker" icon="container" href="/installation#docker">
        Pull the image from Docker Hub. Connects to HTTP and HTTPS servers, and to STDIO servers that run inside the container.
      </Card>
    </CardGroup>

    - **Your server has a public HTTPS URL**: Use any option.
    - **Your server runs on `localhost` or over STDIO**: Use the desktop app or the local Inspector.
    - **You want the Inspector isolated in a container**: Use Docker. Reach servers on your machine at `http://host.docker.internal:PORT`.
  </Step>
  <Step title="Connect a server">
    Open the **Connect** tab in the left sidebar, then click **Add server**.

    - **HTTP**: Paste a URL that ends in `/mcp`. The web app accepts HTTPS URLs only. If the server requires authentication, add a bearer token or use the [OAuth Debugger](/inspector/guided-oauth).
    - **STDIO**: Paste a command such as `npx -y @modelcontextprotocol/server-everything`. STDIO isn't available in the web app. In Docker, the command runs inside the container.

    Each **Connected** server is available in the Playground, Tools, Prompts, and Resources. Connect more from the **Connect** tab anytime.
  </Step>
  <Step title="Send a prompt">
    Click **Open Playground**, and then send this prompt:

    ```
    What can this server do?
    ```
  </Step>
</Steps>

<Check>
Your server shows **Connected** with a green dot in the **Connect** tab, and its tools appear in the Playground's left rail.
</Check>

**Next:** [Playground](/inspector/playground), [OAuth Debugger](/inspector/guided-oauth), and [Evals](/inspector/evals).

## CLI

Access MCPJam from your shell or CI.

<Steps>
  <Step title="Install the CLI">
    The CLI requires Node.js.

    ```bash
    npm i -g @mcpjam/cli
    ```

    To run the CLI without installing it, use this in place of `mcpjam` in the commands on this page:

    ```bash
    npx -y @mcpjam/cli@latest
    ```
  </Step>
  <Step title="Connect a server">
    Run the doctor against your server. It probes the server, connects, initializes, and reads capabilities.

    ```bash
    # HTTP or HTTPS
    mcpjam server doctor --url https://your-server.com/mcp

    # Local STDIO
    mcpjam server doctor --command node --args server.js --cwd /path/to/project
    ```
  </Step>
  <Step title="List the server's tools">
    ```bash
    mcpjam tools list --url https://your-server.com/mcp
    ```
  </Step>
</Steps>

<Check>
The doctor reports a successful connection, and `tools list` prints your server's tools.
</Check>

Evals and `mcpjam cloud` commands also need an MCPJam sign-in or API key. See [eval identity and local data](/cli/local-evals#eval-identity-and-local-data).

**Next:** [CLI overview](/cli/overview), [OAuth conformance](/cli/oauth-conformance), and [CI integration](/cli/ci).

## SDK

The SDK connects to an MCP server from your TypeScript test suite.

<Steps>
  <Step title="Install the SDK">
    The SDK requires Node.js 22 or later.

    ```bash
    npm install @mcpjam/sdk
    ```
  </Step>
  <Step title="Connect a server">
    ```typescript
    import { MCPClientManager } from "@mcpjam/sdk";

    const manager = new MCPClientManager({
      // Local STDIO
      everything: {
        command: "npx",
        args: ["-y", "@modelcontextprotocol/server-everything"],
      },
      // HTTP or HTTPS
      remote: {
        url: "https://your-server.com/mcp",
        requestInit: {
          headers: { Authorization: `Bearer ${process.env.SERVER_TOKEN}` },
        },
      },
    });

    await manager.connectToServer("everything");
    ```
  </Step>
  <Step title="List the server's tools">
    ```typescript
    const tools = await manager.listTools("everything");
    console.log("Tools:", tools.tools.map((t) => t.name));
    ```
  </Step>
</Steps>

<Check>
The script prints the names of your server's tools.
</Check>

End-to-end tests also need an LLM API key. Evals also need an MCPJam sign-in or API key. See [eval identity and local data](/cli/local-evals#eval-identity-and-local-data).

**Next:** [SDK quickstart](/sdk/quickstart), [Connecting servers](/sdk/concepts/connecting-servers), and [Running evals](/sdk/concepts/running-evals).

## API

The API lets your own code work with the MCP servers saved in your MCPJam projects.

<Steps>
  <Step title="Create an API key">
    In the web app, open [**Settings → API keys**](https://app.mcpjam.com/settings/api-keys), and then create a key. Save it as `MCPJAM_API_KEY`.
  </Step>
  <Step title="Connect a server">
    The API works with servers that are saved in a project. First, find your project ID:

    ```bash
    curl "https://app.mcpjam.com/api/v1/projects" \
      -H "Authorization: Bearer $MCPJAM_API_KEY"
    ```

    Then save your server into the project. The response includes the server ID.

    ```bash
    curl -X POST \
      "https://app.mcpjam.com/api/v1/projects/$PROJECT_ID/servers" \
      -H "Authorization: Bearer $MCPJAM_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"name":"my-server","enabled":true,"transportType":"http","url":"https://your-server.com/mcp"}'
    ```

    Servers that you connect in the [web app](https://app.mcpjam.com) are saved to your project too.
  </Step>
  <Step title="List the server's tools">
    ```bash
    curl -X POST \
      "https://app.mcpjam.com/api/v1/projects/$PROJECT_ID/servers/$SERVER_ID/tools" \
      -H "Authorization: Bearer $MCPJAM_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{}'
    ```
  </Step>
</Steps>

<Check>
The response lists your server's tools.
</Check>

**Next:** [MCPJam API guide](/reference/public-api) and [API keys](/reference/api-keys).

## MCP server

The MCP server gives your AI agent access to MCPJam. Add it to Claude, Cursor, or another MCP client. It comes in two forms.

<Tabs>
  <Tab title="Hosted">
    The hosted MCP server connects your agent to your MCPJam account: your projects, saved servers, and evals. You don't install anything or create an API key.

    <Steps>
      <Step title="Add MCPJam to your client">
        Use the server URL `https://mcp.mcpjam.com/mcp`. For example, in Claude Code:

        ```bash
        claude mcp add --transport http mcpjam https://mcp.mcpjam.com/mcp
        ```

        For other clients, see [MCPJam MCP server](/hosted/mcp-server).
      </Step>
      <Step title="Sign in">
        Sign in with your MCPJam account when your client prompts you.
      </Step>
      <Step title="Connect a server">
        The hosted MCP server works with servers that are saved in a project. To save one, connect it in the [web app](https://app.mcpjam.com).
      </Step>
    </Steps>

    **Next:** [MCPJam MCP server](/hosted/mcp-server).
  </Tab>
  <Tab title="Local">
    The local MCP server gives your agent MCPJam's testing engine. It runs on your machine and doesn't need an account. It requires Node.js.

    <Steps>
      <Step title="Add MCPJam to your client">
        For example, in Claude Code:

        ```bash
        claude mcp add mcpjam -- npx -y @mcpjam/cli@latest mcp
        ```

        For other clients, see [MCPJam as an MCP server](/cli/mcp-server).
      </Step>
      <Step title="Connect a server">
        Ask your agent to connect to your server by URL, or by command for a local STDIO server. The agent can then call the server's tools and read its resources and prompts.
      </Step>
    </Steps>

    **Next:** [MCPJam as an MCP server](/cli/mcp-server).
  </Tab>
</Tabs>

## FAQ

<AccordionGroup>
  <Accordion title="Does MCPJam need a database?" icon="database">
    No. The Inspector runs as a web app, a desktop app, a local Inspector, or a Docker image; none of them require you to install or configure a database. Accounts, sharing, and OAuth token storage on [app.mcpjam.com](https://app.mcpjam.com) are handled by the hosted backend; the local Inspector and the desktop app store config locally on disk.
  </Accordion>
  <Accordion title="How do I check which version of Inspector I'm running?" icon="tag">
    The web app, the desktop app, and the local Inspector show the running version in the **Settings** tab under **About**.

    To see the latest published version on npm, run this. It's useful for confirming an `@latest` pull actually moved you forward:

    ```bash
    npm view @mcpjam/inspector version
    ```

    The web app is always on the latest version. The desktop app downloads updates; click **Relaunch to update** to apply one. For the local Inspector, the `@latest` tag in `npx @mcpjam/inspector@latest` pulls the most recent release every run.
  </Accordion>
  <Accordion title="Can MCPJam auto-install MCP servers into my repo?" icon="package">
    Not directly. MCPJam doesn't reach into your repo. The closest workflow is **Skills**: install the MCPJam CLI skill into a project so an agent working in that repo knows how to use MCP tools and call MCPJam against your servers. See [Skills](/inspector/skills).
  </Accordion>
  <Accordion title="Where are my files saved?" icon="folder">
    It depends what you mean. The word covers three different things:

    - **OAuth credentials** from `mcpjam oauth login`: `~/.mcpjam/config.json`. Override per command with `--credentials-out`. See [CLI OAuth login](/cli/oauth-login).
    - **Eval results**: Uploaded to your MCPJam project when `MCPJAM_API_KEY` is set to an MCPJam API key (`sk_…`). See [Saving Results](/sdk/concepts/saving-results).
    - **Inspector UI changes** (server config, client edits): Persisted via the **Save** button in the project view.
  </Accordion>
  <Accordion title="How do I sign out of the hosted app?" icon="log-out">
    Open the **account menu** at the bottom of the sidebar and pick **Sign out**. You'll be returned to the public app as a guest. See [Hosted App → Signing out](/hosted/overview#signing-out).
  </Accordion>
</AccordionGroup>

<Note>
  SDK 10, CLI 6, Vitest 0.3, and later versions require an MCPJam login or `sk_` API key for every eval, including BYOK runs with uploads disabled. Earlier versions keep their existing behavior. For these versions, see [eval identity and local data](/cli/local-evals#eval-identity-and-local-data) for credential precedence, CI setup, failure behavior, and the exact fields sent before an eval.
</Note>
