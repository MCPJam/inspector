Find a task below and pick how you want to run it: the `mcpjam` CLI, MCPJam's local MCP server, or MCPJam's hosted MCP server. Every task links to the page with the full details, and every heading is a link you can share.

## Three ways to run a task

| | CLI | Local MCP | Hosted MCP |
|---|---|---|---|
| **What it is** | The `mcpjam` command | `mcpjam mcp`, MCPJam running as a stdio MCP server inside your MCP client | `https://mcp.mcpjam.com/mcp`, MCPJam's hosted MCP server |
| **Reaches** | Any server your machine can reach, plus your MCPJam projects with `mcpjam cloud` | Any server your machine can reach, including local stdio servers | Servers and evals saved in your MCPJam projects |
| **Account** | None for local testing. Needed for `mcpjam cloud`, `registry`, `readiness start`, `mcpjam test` and `--upload` | None | Your MCPJam account, through OAuth |
| **Set up** | [Installation](/installation) | [MCPJam as an MCP server](/cli/mcp-server) | [MCPJam in Claude](/hosted/claude-connector) |

Local MCP and hosted MCP are different servers with different tools. A task can be available on one and not the other.

<Note>
  Replace everything in angle brackets, such as `<project>`, `<run-id>` or `<tool>`, with your own value. `https://your-server.com/mcp` stands for your MCP server's URL, and `$TOKEN` for an access token in your shell.
</Note>

Some tasks need a feature that's enabled per account. Those tasks say so, and so does their row in each table.

### Install the CLI or add MCPJam to an agent

Install the CLI, or connect MCPJam to an MCP client: the local server needs no account; the hosted server signs you in to your projects.

**Needs:** Node.js for the CLI and local MCP. The hosted MCP server signs you in with your MCPJam account.

<Tabs>
  <Tab title="CLI">
    ```bash
    npm i -g @mcpjam/cli
    mcpjam --version
    ```
  </Tab>
  <Tab title="Local MCP">
    ```bash Claude Code
    claude mcp add mcpjam -- npx -y @mcpjam/cli@latest mcp
    ```

    Other stdio clients launch `npx -y @mcpjam/cli@latest mcp`.
  </Tab>
  <Tab title="Hosted MCP">
    ```bash Claude Code
    claude mcp add --transport http mcpjam https://mcp.mcpjam.com/mcp
    ```

    Then run `/mcp`, choose **mcpjam** and sign in.
  </Tab>
</Tabs>

**Learn more:** [MCPJam as an MCP server](/cli/mcp-server) · [MCPJam in Claude](/hosted/claude-connector)

### Sign in to MCPJam

Store an account session for `mcpjam cloud` commands and check which account you're using. In CI, set `MCPJAM_API_KEY` instead.

**Needs:** an MCPJam account (`mcpjam cloud login`, or an `sk_` key in `MCPJAM_API_KEY`).

<Tabs>
  <Tab title="CLI">
    ```bash
    mcpjam cloud login
    mcpjam cloud whoami
    ```
  </Tab>
  <Tab title="Hosted MCP">
    The tool's `arguments`:

    ```json get_me
    {}
    ```

    The hosted server signs you in with OAuth when you connect it.
  </Tab>
</Tabs>

**Not available on**

- **Local MCP:** not needed; it runs without an MCPJam account.

**Related commands:** `mcpjam cloud logout`

**Learn more:** [`cloud login`](/cli/reference#cloud-login)

### Pin a repository to a project

Write `.mcpjam/project.json` so `mcpjam cloud` commands in this directory use that project by default. The file contains no secrets.

**Needs:** an MCPJam account (`mcpjam cloud login`, or an `sk_` key in `MCPJAM_API_KEY`).

<Tabs>
  <Tab title="CLI">
    ```bash
    mcpjam cloud link <project>
    mcpjam cloud status
    ```
  </Tab>
</Tabs>

**Not available on**

- **Local MCP:** no project tools, because it runs without an MCPJam account.
- **Hosted MCP:** Hosted tools take a `project` argument instead, and default to your most recently updated project.

**Learn more:** [`cloud link`](/cli/reference#cloud-link)

### Configure the clients evals run as

A client is the host identity (model, harness, servers) that environments and eval suites run as. Start from a template.

**Needs:** an MCPJam account (`mcpjam cloud login`, or an `sk_` key in `MCPJAM_API_KEY`).

<Tabs>
  <Tab title="CLI">
    ```bash
    mcpjam cloud clients templates
    mcpjam cloud clients create --name <client-name> --template claude-desktop --project <project>
    ```
  </Tab>
  <Tab title="Hosted MCP">
    Call these tools in order. Each block is the tool's `arguments`.

    ```json list_clients
    {
      "project": "<project>"
    }
    ```

    ```json get_client
    {
      "project": "<project>",
      "client": "<client>"
    }
    ```

    `create_client`, `update_client`, `set_client_servers` and `duplicate_client` are also available. Deleting a client is CLI-only.
  </Tab>
</Tabs>

**Not available on**

- **Local MCP:** no project tools, because it runs without an MCPJam account.

**Related commands:** `mcpjam cloud clients list`, `mcpjam cloud clients get`, `mcpjam cloud clients update`, `mcpjam cloud clients servers`, `mcpjam cloud clients duplicate`, `mcpjam cloud clients delete`

**Learn more:** [Clients](/inspector/clients) · [`cloud clients`](/cli/reference#cloud-clients-commands)

### Set up environments to run against

An environment bundles one client, a server group, and pinned skills and plugin versions. Eval suites and Swarms run against environments.

<Info>
  **Environments** is enabled per account. If it isn't enabled for yours, the request is refused with `403` and `details.code: "FEATURE_UNAVAILABLE"`.
</Info>

**Needs:** an MCPJam account (`mcpjam cloud login`, or an `sk_` key in `MCPJAM_API_KEY`).

<Tabs>
  <Tab title="CLI">
    ```bash
    mcpjam cloud environments list --project <project>
    mcpjam cloud environments resolve --environment <environment>
    ```
  </Tab>
  <Tab title="Hosted MCP">
    Call these tools in order. Each block is the tool's `arguments`.

    ```json list_project_environments
    {
      "project": "<project>"
    }
    ```

    ```json resolve_project_environment
    {
      "project": "<project>",
      "environment": "<environment>"
    }
    ```

    `get_project_environment` and `ensure_adhoc_environment` are also available. Creating, editing, archiving and restoring environments is CLI-only.
  </Tab>
</Tabs>

**Not available on**

- **Local MCP:** no project tools, because it runs without an MCPJam account.

**Related commands:** `mcpjam cloud environments get`, `mcpjam cloud environments create`, `mcpjam cloud environments update`, `mcpjam cloud environments name`, `mcpjam cloud environments archive`, `mcpjam cloud environments restore`, `mcpjam cloud environments ensure-adhoc`

**Learn more:** [`cloud environments`](/cli/reference#cloud-environments-commands)

### Store an API key for evals and sandboxes

Project secrets are encrypted and write-only. The value comes from a file, an environment variable or stdin, never a command-line argument.

**Needs:** an MCPJam account (`mcpjam cloud login`, or an `sk_` key in `MCPJAM_API_KEY`).

<Tabs>
  <Tab title="CLI">
    ```bash
    mcpjam cloud secrets set --name <ENV_VAR_NAME> --delivery materialized --value-file <path>
    mcpjam cloud secrets list
    ```
  </Tab>
  <Tab title="Hosted MCP">
    Call these tools in order. Each block is the tool's `arguments`.

    ```json list_secrets
    {
      "project": "<project>"
    }
    ```

    ```json delete_secret
    {
      "project": "<project>",
      "secret": "<secret>"
    }
    ```

    Setting or rotating a value is CLI-only, so a secret never passes through a chat transcript. Over MCP you can list secrets, read their metadata (`get_secret`) and delete them.
  </Tab>
</Tabs>

**Not available on**

- **Local MCP:** no project tools, because it runs without an MCPJam account.

**Related commands:** `mcpjam cloud secrets show`, `mcpjam cloud secrets update`, `mcpjam cloud secrets rm`

**Learn more:** [CLI reference](/cli/reference)

### Report a bug to MCPJam

Send a bug report or feature gap to the MCPJam team. It's kept for 180 days; don't include secrets.

**Needs:** an MCPJam account (`mcpjam cloud login`, or an `sk_` key in `MCPJAM_API_KEY`).

<Tabs>
  <Tab title="CLI">
    ```bash
    mcpjam cloud feedback --kind bug --summary "<what went wrong>"
    ```
  </Tab>
  <Tab title="Hosted MCP">
    The tool's `arguments`:

    ```json send_feedback
    {
      "kind": "bug",
      "summary": "<what went wrong>"
    }
    ```

    `kind` is `bug`, `missing_capability`, `confusing`, `docs` or `other`.
  </Tab>
</Tabs>

**Not available on**

- **Local MCP:** no project tools, because it runs without an MCPJam account.

**Learn more:** [`cloud feedback`](/cli/reference#cloud-feedback)

### Diagnose a server that fails to connect

One sweep: probe, connect, initialize, list capabilities, and report what failed.

**Needs:** nothing beyond the CLI. No MCPJam account.

<Tabs>
  <Tab title="CLI">
    ```bash
    mcpjam server doctor --url https://your-server.com/mcp --access-token $TOKEN
    ```
  </Tab>
  <Tab title="Local MCP">
    The tool's `arguments`:

    ```json server_doctor
    {
      "url": "https://your-server.com/mcp",
      "accessToken": "<token>"
    }
    ```
  </Tab>
  <Tab title="Hosted MCP">
    The tool's `arguments`:

    ```json diagnose_server
    {
      "project": "<project>",
      "server": "<server>"
    }
    ```

    For a server saved in a project.
  </Tab>
</Tabs>

**Learn more:** [Server inspection](/cli/server-inspection)

### Send a single OAuth request from my machine

Replay one discovery, registration or token request and see the raw response. Private and localhost targets are allowed; `--https-only` applies the hosted app's stricter policy, which helps reproduce a failure seen in the web app.

**Needs:** nothing beyond the CLI. No MCPJam account.

<Tabs>
  <Tab title="CLI">
    ```bash
    mcpjam oauth proxy --url https://auth.example.com/.well-known/oauth-authorization-server
    mcpjam oauth proxy --url https://auth.example.com/register --method POST \
      --header "Content-Type: application/json" --body '{"redirect_uris": ["http://localhost:3000/callback"]}' --https-only
    ```
  </Tab>
</Tabs>

`oauth debug-proxy` takes the same flags and also reads a streaming (SSE) response for a few seconds instead of stopping at the headers.

**Not available on**

- **Local MCP:** no tool for this.
- **Hosted MCP:** no tool for this.

**Related commands:** `mcpjam oauth debug-proxy`

**Learn more:** [`oauth proxy` / `oauth debug-proxy`](/cli/reference#oauth-proxy-%2F-oauth-debug-proxy)

### List tools and call one

Check names, descriptions and schemas, then call a tool with real arguments.

**Needs:** nothing beyond the CLI. No MCPJam account.

<Tabs>
  <Tab title="CLI">
    ```bash
    mcpjam tools list --url https://your-server.com/mcp --access-token $TOKEN
    mcpjam tools call --url https://your-server.com/mcp --access-token $TOKEN \
      --tool-name <tool> --tool-args '{"query": "test"}'
    ```
  </Tab>
  <Tab title="Local MCP">
    Call these tools in order. Each block is the tool's `arguments`.

    ```json connect_server
    {
      "name": "<connection>",
      "command": "node",
      "args": [
        "dist/server.js"
      ]
    }
    ```

    ```json list_tools
    {
      "server": "<connection>"
    }
    ```

    ```json call_tool
    {
      "server": "<connection>",
      "tool": "<tool>",
      "arguments": {
        "query": "test"
      }
    }
    ```

    `connect_server` takes `url` (with optional `accessToken` and `headers`) for HTTP servers, or `command`, `args`, `env` and `cwd` for stdio. Check `isError` in the `call_tool` result for tool-level failures.
  </Tab>
  <Tab title="Hosted MCP">
    Call these tools in order. Each block is the tool's `arguments`.

    ```json list_server_tools
    {
      "project": "<project>",
      "server": "<server>"
    }
    ```

    ```json call_server_tool
    {
      "project": "<project>",
      "server": "<server>",
      "toolName": "<tool>",
      "parameters": {
        "query": "test"
      }
    }
    ```

    Claude asks before `call_server_tool` runs, because your server's tools can change things.
  </Tab>
</Tabs>

**Learn more:** [Tools, resources & prompts](/cli/tools-resources-prompts)

### Chat with my servers through a model

Send a Playground turn and get the reply with its tool calls, latency and token usage. Spends credits.

**Needs:** an MCPJam account (`mcpjam cloud login`, or an `sk_` key in `MCPJAM_API_KEY`).

<Tabs>
  <Tab title="CLI">
    ```bash
    # Start a conversation; the output includes its sessionId
    mcpjam cloud sessions send --project <project> \
      --message "<message>" --idempotency-key <turn-key>

    # Continue it
    mcpjam cloud sessions send --session <session-id> \
      --message "<message>" --idempotency-key <next-turn-key>
    ```
  </Tab>
  <Tab title="Hosted MCP">
    The tool's `arguments`:

    ```json send_chat_message
    {
      "project": "<project>",
      "sessionId": "<session-id>",
      "message": "<message>",
      "idempotencyKey": "<turn-key>"
    }
    ```

    Leave out `sessionId` to start a new conversation. Claude asks before this runs, because it calls your servers' tools.
  </Tab>
</Tabs>

Reuse an idempotency key only to retry the same turn; a retry with the same key returns the completed turn instead of running and billing it again.
