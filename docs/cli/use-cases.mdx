Think of MCPJam as **devtools for your MCP server**: you point it at a server, watch what happens, and check it before your users do. Pick what you want to do below and follow the steps.

**What you'll walk away with**

- The command that does what you need, ready to copy
- The same task as MCP tool calls, if you'd rather ask your agent
- A link to the full docs for each step

## Before you start

Install the CLI. That's all the first two walkthroughs need: no account.

```bash
npm i -g @mcpjam/cli
mcpjam --version
```

<Note>
  Replace everything in angle brackets, such as `<project>` or `<tool>`, with your own value. `https://your-server.com/mcp` stands for your server's URL.
</Note>

## What do you want to do today?

<Tabs>
  <Tab title="Debug my server">
    <Steps>
      <Step title="Run a checkup">
        One command probes, connects, initializes and tells you what failed.

        ```bash
        mcpjam server doctor --url https://your-server.com/mcp
        ```
      </Step>
      <Step title="See its tools and call one">
        ```bash
        mcpjam tools list --url https://your-server.com/mcp
        mcpjam tools call --url https://your-server.com/mcp \
          --tool-name <tool> --tool-args '{"query": "test"}'
        ```
      </Step>
      <Step title="Signing in? Do it once">
        For an OAuth server, sign in once and reuse the saved credentials in any command.

        ```bash
        mcpjam oauth login --url https://your-server.com/mcp --credentials-out creds.json
        mcpjam tools list --url https://your-server.com/mcp --credentials-file creds.json
        ```
      </Step>
    </Steps>

    <Check>
      You've seen your server's tools and called one. Next: open the **Check it's ready to ship** tab, or read [Server inspection](/cli/server-inspection).
    </Check>
  </Tab>
  <Tab title="Check it's ready to ship">
    Two different checks. **Conformance** grades your server against the MCP specification. **Directory readiness** grades it against what a directory such as Claude or OpenAI asks for before you submit. Passing one doesn't mean you pass the other.

    <Steps>
      <Step title="Check conformance">
        ```bash
        mcpjam conformance run --url https://your-server.com/mcp
        ```
      </Step>
      <Step title="Check it for a directory">
        ```bash
        mcpjam readiness check claude https://your-server.com/mcp
        mcpjam readiness check openai https://your-server.com/mcp --submission-mode mcp-only
        ```
      </Step>
      <Step title="Catch breaking changes before you deploy">
        Save a snapshot, deploy, and compare.

        ```bash
        mcpjam server export --url https://your-server.com/mcp > before.json
        mcpjam server diff --baseline before.json --url https://your-server.com/mcp --fail-on breaking
        ```
      </Step>
    </Steps>

    <Check>
      You know which checks fail and why. Fix them and run the same commands again. More in the [CLI reference](/cli/reference#protocol-conformance).
    </Check>
  </Tab>
  <Tab title="Run evals in CI">
    A tool description change can quietly change how models use your server. Evals catch that before it ships.

    <Steps>
      <Step title="Sign in">
        Evals run on MCPJam, so you need an account.

        ```bash
        mcpjam cloud login
        ```
      </Step>
      <Step title="Check and run your suite">
        ```bash
        mcpjam cloud eval validate --file .mcpjam/evals/<suite-file>.yaml
        mcpjam cloud eval run --file .mcpjam/evals/<suite-file>.yaml --project <project>
        ```
      </Step>
      <Step title="Fail the build when quality drops">
        ```bash
        mcpjam cloud eval gate --run <run-id> --min-pass-rate-percent 90
        ```
      </Step>
    </Steps>

    <Check>
      Your suite runs and the gate passes or fails your build. Next: [Evals](/inspector/evals).
    </Check>
  </Tab>
  <Tab title="Test with simulated users">
    <Info>
      Swarms are enabled per account.
    </Info>

    <Steps>
      <Step title="Describe a user and what they want">
        ```bash
        mcpjam cloud login
        mcpjam cloud personas create --name "<persona-name>" --role "<role>"
        mcpjam cloud goals create --goal "<what the user wants>" --persona <persona-id> --max-turns 8
        ```
      </Step>
      <Step title="Run it against your server">
        ```bash
        mcpjam cloud goals run --goal-id <goal-id> --project <project>
        ```
      </Step>
      <Step title="Read the scorecard">
        ```bash
        mcpjam cloud goals scorecard --run <goal-run-id>
        ```
      </Step>
    </Steps>

    <Check>
      You've seen how a simulated user got on with your server. More in [`cloud goals`](/cli/reference#cloud-goals-commands).
    </Check>
  </Tab>
  <Tab title="Share with my team">
    <Steps>
      <Step title="Sign in and pick a project">
        ```bash
        mcpjam cloud login
        mcpjam cloud link <project>
        ```
      </Step>
      <Step title="Add your server to it">
        ```bash
        mcpjam cloud projects servers connect --url https://your-server.com/mcp --project <project>
        ```
      </Step>
      <Step title="Running it on localhost? Open a tunnel">
        ```bash
        mcpjam cloud tunnel http://localhost:9090/mcp --server <server-name> --project <project>
        ```
      </Step>
    </Steps>

    <Check>
      Your team can open the same server in MCPJam. More in [`cloud projects servers`](/cli/reference#cloud-projects-servers-commands).
    </Check>
  </Tab>
</Tabs>

## Rather ask your agent?

Every walkthrough above also works as MCP tool calls. MCPJam runs two MCP servers:

| | Local MCP | Hosted MCP |
|---|---|---|
| **Start it** | `mcpjam mcp` in your MCP client | `https://mcp.mcpjam.com/mcp` |
| **Reaches** | Any server your machine can reach | Servers saved in your MCPJam projects |
| **Account** | None | Yes, through OAuth |
| **Set up** | [MCPJam as an MCP server](/cli/mcp-server) | [MCPJam in Claude](/hosted/claude-connector) |

They have different tools. For example, to list a server's tools and call one:

<Tabs>
  <Tab title="Local MCP">
    ```json connect_server
    { "name": "my-server", "url": "https://your-server.com/mcp" }
    ```

    ```json call_tool
    { "server": "my-server", "tool": "<tool>", "arguments": { "query": "test" } }
    ```
  </Tab>
  <Tab title="Hosted MCP">
    ```json list_server_tools
    { "project": "<project>", "server": "<server>" }
    ```

    ```json call_server_tool
    { "project": "<project>", "server": "<server>", "toolName": "<tool>", "parameters": { "query": "test" } }
    ```
  </Tab>
</Tabs>
