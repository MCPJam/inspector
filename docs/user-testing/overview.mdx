User Testing lets people try your MCP server through a shareable chat link. You create a **study** with a client, model, and server setup, choose who can open it, and optionally give testers tasks to try. MCPJam records their conversations with their consent so you can review what actually happened.

## What a study contains

| Part | What it controls |
| --- | --- |
| **Client and servers** | The experience testers open and which MCP servers the assistant can use. A study uses one client and model setup. |
| **Access** | Who can open the study, such as team members, people you invite, or people with the link, depending on your sharing settings. |
| **Tasks** | Optional instructions testers see in the chat. Describe an outcome, such as finding blocked tasks on a board before standup. |
| **Per-turn ratings** | Optional stars or thumbs, with comments, that testers can leave on assistant replies. |
| **Sessions** | Recorded tester conversations you can inspect alongside tool calls and any ratings they left. |

## When to use User Testing

- Give QA teammates or beta testers a way to try a staging server through a browser link.
- See what people ask when they have a goal but no prescribed prompt.
- Find unclear replies or widget interactions that are hard to spot from a tool response alone.

Use [Swarms](/swarms/overview) to explore a goal with simulated users across multiple targets, or [Evaluate](/evaluate/overview) to check a known behavior repeatedly.
