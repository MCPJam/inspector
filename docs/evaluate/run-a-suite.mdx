A run executes every case in a suite against each client and model pair you pick. Each case runs once per iteration, so a run of 3 cases at 2 iterations on 2 client and model pairs produces 12 iterations.

## What a run needs

| Need | Where it comes from |
|---|---|
| Cases | At least one saved case. Generated drafts don't run until you add them to the suite. |
| Servers | Each client in the suite runs with a server group, and the run connects the servers in that group. Set it in **Suite settings** under **Where it runs**. A client with no server group would connect no servers, so the run won't start. |
| Clients and models | The client and model pairs saved on the suite. You can change them for one run in the **Set up run** sheet. |
| Model access | MCPJam credits, or a model from your own provider. See [What a run can access](/evaluate/what-a-run-can-access). |
| Eval iterations | Your organization's eval iteration allowance. Every iteration counts against it. |

A suite saved without clients, such as one created by the SDK, shows a **Servers** picker in the sheet instead. Pick the server group the run should use; the suite itself is not changed.

## Start a run

<Tabs>
  <Tab title="Inspector">
    <Steps>
      <Step title="Open the suite">
        In the Evaluate tab, open **Suites** and pick a suite. You can also click **Run** on **Overview** and choose the suite from the list.
      </Step>
      <Step title="Click Run">
        The Set up run sheet opens, with the suite name in its title.
      </Step>
      <Step title="Set the iteration count">
        **Iterations per case** takes 1 to 10. It starts at the count you used last time for this suite, or the suite's default, and never below the suite's minimum.
      </Step>
      <Step title="Check the clients and models">
        **Where it runs** lists each client with the models it runs. Adding or removing a client or model here changes this run only; the suite keeps its saved pairs.
      </Step>
      <Step title="Start">
        The footer multiplies it out, for example "3 cases × 2 repetitions × 2 client:model combos", with the total number of iterations beside it. Click **Start run**.
      </Step>
    </Steps>

    {/* Screenshot: Set up run · Weather suite sheet with Iterations per case at 2, the Where it runs table with two clients, and the footer reading 3 cases × 2 repetitions × 2 client:model combos = 12 iterations */}

    **Suite settings** in the sheet closes it and opens the suite's settings, where the saved clients, models and server groups live.
  </Tab>
  <Tab title="CLI: local">
    `mcpjam test` runs a suite file on your machine. It reads the file, not a suite saved in the app, and binds each server name to a local MCP config such as `./.mcp.json`. See [Local evals](/cli/local-evals).

    ```bash
    export ANTHROPIC_API_KEY=sk-ant-...
    mcpjam test .mcpjam/evals/example.yaml
    ```
  </Tab>
  <Tab title="CLI: hosted">
    `mcpjam cloud eval run` starts a run of a suite saved in your project. `--wait` polls until the run finishes and exits on its verdict.

    ```bash
    mcpjam cloud eval run \
      --suite "My eval suite" \
      --project "My project" \
      --iterations 3 \
      --wait
    ```

    See [`cloud eval run`](/cli/reference#cloud-eval-run) for target selection and exit codes.
  </Tab>
</Tabs>

### Run one case

<Tabs>
  <Tab title="Inspector">
    Open the case and click **Run** in the case editor. A "Set up run" sheet opens with the case title under it; pick the iterations and the clients and models, then click **Run test case**.

    Unsaved edits are saved before the run starts. A new case has to be saved once before it can run.
  </Tab>
  <Tab title="CLI: local">
    ```bash
    mcpjam test .mcpjam/evals/example.yaml --case c_reads_a_note
    ```

    `--case` takes the case's authored id and can be repeated.
  </Tab>
  <Tab title="CLI: hosted">
    ```bash
    mcpjam cloud eval cases run --suite "My eval suite" --case "Reads a note"
    ```
  </Tab>
</Tabs>

### Run again

On a run page, **Run again** opens the same Set up run sheet for that suite, so you can repeat the run or change its iterations and models first.

<Note>
  As a guest, **Run** in the case editor opens a simpler "Set up run" sheet: the iteration count and a client with its models, then **Run test case**. It has no **Suite settings** button.
</Note>

## Cancel a run

While a run is pending, running or grading, **Cancel run** takes the place of **Run again** on the run page. It stops every client and model pair of that launch at once, including a run whose iterations have finished but whose judge is still grading. On the suite page, **Cancel run** appears while any run of the suite is still going and stops all of them.

Iterations that had not finished are recorded as cancelled, not failed. The run page counts them in their own **Cancelled** column and leaves them out of the pass and fail counts, so a stopped run does not read as a broken server. From the CLI, `mcpjam cloud eval run --wait` exits `5` for a cancelled run, the code for a run with no valid verdict.

## Why Run is disabled

Hover the disabled button to see the reason. The suite page's **Run** and the sheet's **Start run** each check different things.

| Message | Cause | Fix |
|---|---|---|
| "Add a test case first." | The suite has no saved cases. | Add a case. If generated drafts are waiting, the message says so; add them to the suite first. |
| "A suite or replay is already in progress." | A run of this suite is still going. | Wait for it, or click **Cancel run**. |
| "Finish the in-progress test case run first." | A single-case run is still going. | Wait for it to finish. |
| "Configure suite servers before running the full suite." | A suite with no clients has no servers to connect. | Open **Suite settings** and give the suite a server group. |
| "Eval iteration limit reached. Resets …" | Your organization has used its eval iterations for this period. | Wait for the reset time shown, or move to a plan with a larger allowance. |
| "Choose at least one client and model." | Every client or model was removed in the sheet, or a client has no model. | Add a client and pick a model under **Where it runs**. |
| "A selected client has no server group, so its run would connect no servers." | A client in the run has no server group. | Pick a server group for it in **Suite settings**. |
| "Pick a server group to run this suite." | The suite has no clients and no group is picked. | Pick one in **Servers**. |
| "Out of MCPJam credits · resets in …" | Every model in the run uses MCPJam credits and your organization has none left. | Switch to a model from your own provider, or wait for the reset. |
| "Fix the setup problem above before running." | The sheet found a problem it can't work around, such as a server that is no longer in the project. | Follow the notice above the message: re-add the server or point the suite at another one. |
| "Save the test case before running." | The case is a new, unsaved draft. | Click **Save** in the case editor. |

A server that is in the project but not connected does not block the run. The sheet names it ("… isn't connected. Start tries to connect it.") with a **Connect** button if you want to connect it first.

## Execution time limits

Five rows in **Suite settings** cap how long each part of a run may take. An empty field shows the platform default it inherits.

| Setting | What it limits |
|---|---|
| **Per-turn timeout** | One assistant turn, including the tool steps it drives. |
| **Per-tool-call timeout** | One MCP request. A per-server override pinned on the client still wins. |
| **Per-iteration timeout** | One iteration. An iteration that runs out of time fails alone; the others keep going. |
| **Whole-run timeout** | The whole run. It is a backstop; the per-iteration limit is what usually fires. |
| **Model call retries** | How many times one model call is retried. Never applied to a live stream. |

See the [suite settings reference](/evaluate/reference/suite-settings) for units, ceilings and API fields.
