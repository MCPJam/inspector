An assertion is a deterministic rule over one iteration's transcript: the same transcript always gets the same result. Add one from **Add assertion or action** in the case editor, or from **Add an assertion on the whole run**. The picker groups them under the stage of the user value chain their result is reported at, and the tables below follow that grouping.

The Scope column says where an assertion can be graded:

- Turn or whole run: added after a step, it grades only the transcript up to that point; added on the whole run, it grades the finished transcript once.
- Whole run: graded once, over the finished transcript.
- At a step (live view): graded against the rendered view at that point in the run. It cannot be re-graded from a stored trace.

The Suite file column is the assertion's name in a suite file (`type:` on an assertion, `kind:` for a live-view check).

## Discovery

| Assertion | Passes when | Scope | Suite file |
| --- | --- | --- | --- |
| Tool descriptions meet the minimum length | Every tool's description is at least the minimum length (20 characters unless set). | Whole run | `toolDescriptionsPresent` |
| Every tool declares annotations | Every tool declares annotations, including any hints you list as required. | Whole run | `toolAnnotationsPresent` |
| Tool names are unique within each server | No server exposes two tools with the same name. | Whole run | `toolNamesUnique` |
| No tool description marks itself deprecated | No tool's own description says it is deprecated. Advisory only. | Whole run | `noDeprecatedToolExposed` |
| Input schemas have an object root and documented parameters | Every input schema has an object root and documents its parameters. | Whole run | `toolInputSchemasWellFormed` |
| Every tool declares an output schema | Every tool declares an output schema. | Whole run | `toolOutputSchemasPresent` |

## Selection

| Assertion | Passes when | Scope | Suite file |
| --- | --- | --- | --- |
| No tools should be called | The model called no tool. Marks the case negative. | Whole run | — |
| Tools must be called in this exact order | The model called the expected tools in strict order with no extra calls. | Whole run | — |
| Tool was called with… | The named tool was called with arguments that match, under the assertion's argument matching mode. | Turn or whole run | `toolCalledWith` |
| Tool was called at least once | The named tool was called at least once. Arguments are not checked. | Turn or whole run | `toolCalledAtLeastOnce` |
| Tool was never called | The named tool was not called. | Turn or whole run | `toolNeverCalled` |
| Only these tools may be called | No tool outside the list was called. It does not require the listed tools to be called. An empty list means no tool at all. | Turn or whole run | `onlyToolsCalled` |
| First tool called was… | The first tool call was the named tool. | Turn or whole run | `firstToolWas` |
| Fewer than N tool calls | Strictly fewer than N calls were made (to one tool, if named). | Turn or whole run | `toolCallCountUnder` |
| Tool called before another tool | Every call to the second tool came after a call to the first. Passes if the second tool never ran. | Turn or whole run | `toolCalledBefore` |
| No tool marked deprecated was called | No called tool's own description marks it deprecated. Advisory only. | Whole run | `noDeprecatedToolCalled` |
| No tool marked destructive was called | No called tool declares `destructiveHint: true`. Errors, rather than passes, when no tool declares annotations. | Whole run | `noDestructiveToolCalled` |

## Tool call

| Assertion | Passes when | Scope | Suite file |
| --- | --- | --- | --- |
| Arguments match the tool's schema | Every call's arguments validate against the tool's declared input schema. | Whole run | `argumentsMatchToolSchema` |
| No identical call repeated back-to-back | No call repeats the call immediately before it with equal arguments. Advisory only. | Turn or whole run | `noRepeatedIdenticalCall` |
| Tool input matches regex | Between the minimum (default 1) and maximum number of calls to the tool have input matching every pattern. All patterns must match within one call. | Turn or whole run | `toolInputMatches` |

## Response

| Assertion | Passes when | Scope | Suite file |
| --- | --- | --- | --- |
| No tool errors | No tool call returned an MCP error or a transport failure. After a step it reads **No tool errors so far**. | Turn or whole run | `noToolErrors` |
| Tool call under N ms | Every call (to one tool, if named) finished in strictly under N ms. | Whole run | `toolLatencyUnder` |
| Tool result contains… | A tool result contains the text. Case-insensitive unless set. | Whole run | `toolResultContains` |
| Tool output matches regex | Between the minimum (default 1) and maximum number of tool results match every pattern. | Whole run | `toolResultMatches` |
| Tool result matches schema… | Every tool result validates against the JSON Schema you provide. | Whole run | `toolResultMatchesSchema` |
| Tool result under N bytes | Every tool result is strictly under N bytes, as the server returned it. | Whole run | `toolResultSizeUnder` |
| Tool errors name an input | Every tool error message names one of the tool's inputs or a value the call sent. Advisory only. | Whole run | `toolErrorNamesInput` |
| Full pages include a next-page link | A page whose length equals its requested limit carries continuation metadata. Advisory only. | Whole run | `fullPageHasContinuation` |

| Assertion | Passes when | Scope | Suite file |
| --- | --- | --- | --- |
| Response contains… | The final assistant message contains the text. Case-insensitive unless set. | Turn or whole run | `responseContains` |
| Response close to… | The final assistant message is within the maximum edit distance of a reference text. | Turn or whole run | `responseCloseTo` |
| Response matches regex… | The final assistant message matches the regular expression. | Turn or whole run | `responseMatches` |

| Text visible | The text is visible in the rendered view. | At a step (live view) | `kind: textVisible` |
| Element visible | The element is visible in the rendered view. | At a step (live view) | `kind: elementVisible` |
| Element hidden | The element is hidden in the rendered view. | At a step (live view) | `kind: elementHidden` |
| Input value equals | The input's value equals the text you set. | At a step (live view) | `kind: inputValue` |

## Budgets

| Assertion | Passes when | Scope | Suite file |
| --- | --- | --- | --- |
| Token budget under N | Input plus output tokens for the whole iteration total strictly less than N. | Whole run | `tokenBudgetUnder` |
| Fewer than N user turns | The iteration used strictly fewer than N user turns. | Whole run | `turnCountUnder` |

<Note>
  Token budget under N is not a spend control. Token counts are not comparable across models, and a fixed ceiling goes stale whenever a prompt or model changes. To see what a suite costs, read the cost on each run in [Read results](/evaluate/read-results). To fail CI when a change makes a suite more expensive than its baseline, use `--max-cost-increase-percent` with `mcpjam cloud eval compare` ([CI](/cli/ci)).
</Note>

## Argument matching

**Tool was called with…** compares arguments in one of three modes. The suite's default for route matching is set under **Edit tool-call matching** in suite settings.

| Mode | Matches when |
| --- | --- |
| **Partial** (default) | Every argument you set matches. The call may carry extra arguments. |
| **Exact** | The arguments equal what you set, with no extra keys. |
| **Ignore** | The tool was called. Arguments are not compared. |

In partial mode, these strings match any value of that type instead of the literal string: `"any"`, `"string"`, `"number"`, `"boolean"`, `"object"`, `"array"`, `"null"`. Exact mode treats them as literals.

```yaml
- id: a1
  kind: assert
  assertion:
    type: toolCalledWith
    toolName: search_notes
    args:
      args:
        query: "string"   # any string
        limit: 5          # exactly 5
      argumentMatching: partial
```

## Route checks

The case editor's route question, **Which tool should handle it?**, is an assertion on the whole run. Its two strictness levels sit under **Matching options**.

| Choice | Passes when |
| --- | --- |
| Reach the tool | The named tools were called, in any order. Extra calls are allowed. |
| Exact route | The named tools were called in strict order, with no extra calls; arguments are compared as pinned. Added from the picker as **Tools must be called in this exact order**. |
| **No tool should be called** | No tool was called. Added from the picker as **No tools should be called**. **Use tools instead** reverses it. |
| Any route | The case names no route and is graded by its other evaluators. |

## Suite defaults and case assertions

A suite can carry default assertions that apply to every case. A case relates to them in one of three modes:

| Mode | The case is graded by |
| --- | --- |
| `inherit` | The suite's default assertions only. |
| `extend` | The suite's defaults, then the case's own list. |
| `replace` | The case's own list only. An empty list turns the suite's defaults off for that case. |

Assertions you add to a case in the app extend the suite's. A case set to replace shows "Suite evaluators replaced for this case", with **Apply suite evaluators too** to switch it back. Over the API the mode is part of the case's `checks` field, `{ mode, list }`. In the SDK it is the case evaluator override; see [Running evals](/sdk/concepts/running-evals).

## Required and Advisory

| Role | A failure | Suite file |
| --- | --- | --- |
| **Required** (default) | Fails the iteration. | `role: required` |
| **Advisory** | Is shown on the result and never fails the iteration. | `role: advisory` |

The six assertions marked "Advisory only" above are heuristics, so they cannot be Required: the picker labels them **Advisory only** and a save that marks one Required is refused. The route check is always Required. When available, an assertion's editor shows a Required / Advisory control.
