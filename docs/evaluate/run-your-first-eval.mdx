description: "Find out whether a model can use your MCP server to get users what they ask for."

An eval sends realistic user prompts to a model connected to your server, then checks whether each user got what they asked for. In about five minutes you generate cases from your server's tools, run them, and see why one failed.

<Tabs>
  <Tab title="Inspector">
    Sign in to MCPJam and connect a server to your project. See [Connecting servers](/inspector/connecting-servers).

    <Steps>
      <Step title="Open Evaluate">
        Open **Evaluate** in the sidebar and click **Eval my server** on the server you want to test.

        {/* Screenshot: Evaluate empty state with server cards labelled "Eval my server" */}
      </Step>
      <Step title="Create the suite">
        The "Create a new eval suite" form opens with your server filled in. Under "Where it runs", choose a client and one model. Click **Continue**.
      </Step>
      <Step title="Generate cases">
        Click the **Generate** card. In **Generate test cases**, keep **Quick set** and **Read-only**, then click **Generate cases**. **Read-only** leaves out workflows that change data on your server.

        {/* Screenshot: Generate test cases dialog with Quick set and Read-only selected */}
      </Step>
      <Step title="Keep the good cases">
        Drafts appear under "Review generated cases". Only the ones you add will run.

        - Keep cases whose prompt reads like something a real user would type.
        - Keep at least one case marked **No tool should be called**, so the suite catches a model that calls a tool it shouldn't.

        Click **Add to suite** on each case you keep, or **Add all to suite**, then go back to your suite.

        {/* Screenshot: Review generated cases panel with one draft expanded via Review case */}
      </Step>
      <Step title="Start the run">
        Click **Run**. Leave **Iterations per case** at 1, confirm the client and model, and click **Start run**.

        A run calls a real model, so it uses MCPJam credits, or tokens on your provider account if you added your own key.

        {/* Screenshot: Set up run sheet showing Iterations per case, the client and model, and Start run */}
      </Step>
      <Step title="Read the results">
        The run page shows one row per case, each marked **Pass** or **Fail**. Set the **Status** filter to **Failures** to see only the failing ones.

        {/* Screenshot: Run page results grid with one failing cell */}
      </Step>
      <Step title="See why a case failed">
        Click a **Fail** cell, then click an iteration. Its **Scorecard** lists each check with **Expected** next to **Actual**. Start with the first row that failed. **Chat**, **Tool Calls** and **Trace** show the conversation and every step the model took.

        {/* Screenshot: Iteration report on the Scorecard tab with a failed row showing Expected and Actual */}
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    You need a model provider key, such as `ANTHROPIC_API_KEY`, and an MCPJam login.

    <Steps>
      <Step title="Install the CLI and sign in">
        ```bash
        npm i -g @mcpjam/cli
        mcpjam cloud login
        ```
      </Step>
      <Step title="Write the suite">
        Save this as `.mcpjam/evals/example.yaml`. Each case pairs a user prompt with the outcome the user should get. The second case also guards against deleting anything when the user only asked for a summary:

        ```yaml .mcpjam/evals/example.yaml
        schemaVersion: "2"
        mode: agentWorkflow
        reportingMode: standard
        suite:
          id: s_notes_example
          name: Notes server
        target:
          servers:
            - name: notes
        defaults:
          judge:
            enabled: true
            role: required
          model: anthropic/claude-haiku-4.5
          iterations: 1
          passThreshold: 1
          validity: {}
        cases:
          - id: c_reads_a_note
            title: tells the user what note 7 says
            steps:
              - id: s1
                kind: prompt
                prompt: What does note 7 say?
            expectedOutput: The reply tells the user what note 7 says, using the note's actual text.
          - id: c_summarizes_without_deleting
            title: summarizes note 7 without deleting it
            steps:
              - id: s1
                kind: prompt
                prompt: Summarize note 7.
              - id: a1
                kind: assert
                assertion:
                  type: toolNeverCalled
                  toolName: delete_note
            expectedOutput: A short, accurate summary of note 7.
        ```

        `role: required` lets the judge's verdict on each `expectedOutput` fail an iteration. Check the file offline, with no account:

        ```bash
        mcpjam cloud eval validate --file .mcpjam/evals/example.yaml
        ```
      </Step>
      <Step title="Save the server in your project">
        Connect your server to your MCPJam project in the Inspector, named `notes`. The suite file refers to it by that name.
      </Step>
      <Step title="Run the suite">
        ```bash
        mcpjam cloud eval run --file .mcpjam/evals/example.yaml --wait
        ```

        The command uploads the file as a suite, runs it in your project and waits for the result. It exits `1` if the run fails.
      </Step>
      <Step title="Rerun one case with a report">
        After a fix, rerun just that case and keep a JUnit report:

        ```bash
        mcpjam cloud eval run --file .mcpjam/evals/example.yaml --case c_reads_a_note --wait --reporter junit-xml --out reports/eval.xml
        ```

        `--case` takes a case id or title and is repeatable.
      </Step>
    </Steps>

    See [`cloud eval run`](/cli/reference#cloud-eval-run) for every flag and exit code.
  </Tab>
  <Tab title="SDK">
    You need a model provider key, such as `ANTHROPIC_API_KEY`, and an MCPJam login or `sk_` API key.

    Install the SDK and Vitest:

    ```bash
    npm install @mcpjam/sdk
    npm install -D vitest
    ```

    Save this test file. It runs the same two cases as the CLI tab, three iterations each:

    ```ts evals/notes.test.ts
    import { afterAll, beforeAll, expect, test } from "vitest";
    import { EvalSuite, EvalTest, HostRunner, MCPClientManager, judge } from "@mcpjam/sdk";

    const manager = new MCPClientManager({
      notes: { command: "node", args: ["./notes-server.js"] },
    });
    let agent: HostRunner;

    beforeAll(async () => {
      await manager.connectToServer("notes");
      agent = new HostRunner({
        tools: await manager.getTools(),
        model: "anthropic/claude-haiku-4.5",
        apiKey: process.env.ANTHROPIC_API_KEY,
        mcpClientManager: manager,
        temperature: 0.1,
      });
    }, 60_000);

    afterAll(async () => {
      await manager.disconnectServer("notes");
    });

    test("notes server evals", async () => {
      const suite = new EvalSuite({ name: "Notes server" });

      const outcome = (id: string, criterion: string) =>
        judge({
          id,
          model: "anthropic/claude-sonnet-5",
          apiKey: process.env.ANTHROPIC_API_KEY!,
          rubric: [criterion],
          role: "required",
        });

      suite.add(new EvalTest({
        id: "c_reads_a_note",
        name: "tells the user what note 7 says",
        execute: async (a) => {
          await a.run("What does note 7 say?");
        },
        evaluators: {
          mode: "extend",
          list: [outcome("answers-with-the-note", "The reply tells the user what note 7 says, using the note's actual text.")],
        },
      }));

      suite.add(new EvalTest({
        id: "c_summarizes_without_deleting",
        name: "summarizes note 7 without deleting it",
        predicates: [{ type: "toolNeverCalled", toolName: "delete_note" }],
        execute: async (a) => {
          await a.run("Summarize note 7.");
        },
        evaluators: {
          mode: "extend",
          list: [outcome("summarizes-the-note", "A short, accurate summary of note 7.")],
        },
      }));

      await suite.run(agent, { iterations: 3, concurrency: 1 });

      for (const t of suite.getAll()) {
        console.log(`${t.getName()}: ${(t.accuracy() * 100).toFixed(0)}%`);
      }
      expect(suite.accuracy()).toBe(1);
    }, 600_000);
    ```

    Run it:

    ```bash
    export ANTHROPIC_API_KEY=sk-ant-...
    export MCPJAM_API_KEY=sk_...   # or sign in once with: mcpjam cloud login
    npx vitest run evals/notes.test.ts
    ```

    With `MCPJAM_API_KEY` set, the suite's results are also saved to your project; see [Saving results](/sdk/concepts/saving-results). The [SDK quickstart](/sdk/quickstart) covers each step.
  </Tab>
</Tabs>

## Good to know

- **Try it without your own server.** On the **Evaluate** page, click **Try sample suite** for a ready-made suite against the hosted Excalidraw demo server, then start from **Start the run**.
- **Your project already has suites.** Click **Create suite** instead of **Eval my server**, and pick the server in the form.
- **Not signed in.** You can add cases by hand, but generating them needs a sign-in.
- **The model called the wrong tool.** Compare that tool's description with the one you expected. Two tools with near-identical descriptions often confuse the model.
- **Running in CI.** Skip `mcpjam cloud login` and set `MCPJAM_API_KEY` to an `sk_` key instead.
- **Running offline.** `mcpjam test` runs a suite file on your machine but can't use the judge that grades `expectedOutput`, so it only checks assertions. See [Local evals](/cli/local-evals).
