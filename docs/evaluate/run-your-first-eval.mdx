title: "Run your first eval"
description: "Generate cases from a connected server, run them against a model, and read why a case failed."

This tutorial takes about five minutes. You create a suite from a server you already connected, generate cases from its tools, run them against one model, and open a failing iteration to see which stage broke.

## Before you start

- Sign in to MCPJam. Generating cases needs an account: as a guest, the **Generate test cases** dialog asks you to sign in, though you can still add cases by hand.
- Connect at least one server to your project. See [Connecting servers](/inspector/connecting-servers).

<Tabs>
  <Tab title="Inspector">
    <Steps>
      <Step title="Open Evaluate and pick a server">
        Open **Evaluate** in the sidebar. With no suites yet, the page reads "Automate the checks you'd run by hand" and shows a card for each server in your project. Click **Eval my server** on the server you want to test. If the project already has suites, click **Create suite** at the top of the tab instead and pick the server in the form.

        {/* Screenshot: Evaluate empty state with server cards labelled "Eval my server" and the "Try sample suite" button */}

        To see a finished example first, click **Try sample suite**. It creates an "Excalidraw quickstart" suite with cases already written against the hosted Excalidraw demo server. Continue from step 5.

        The first time you open an empty Evaluate tab, a short tour may start. Skip it or step through it; it ends on the same form as the next step.
      </Step>
      <Step title="Create the suite">
        The "Create a new eval suite" form opens with the suite name and server filled in. Under "Where it runs", choose a client and one model. One model keeps the first run small. Click **Continue**.
      </Step>
      <Step title="Generate cases">
        The new suite has no cases yet. Click the **Generate** card. In **Generate test cases**, keep **Quick set** and **Read-only**, then click **Generate cases**.

        **Read-only** leaves out workflows that change data on your server, which is what you want while you are still reading the results.

        {/* Screenshot: Generate test cases dialog with Quick set and Read-only selected */}
      </Step>
      <Step title="Review the generated cases">
        Drafts appear under "Review generated cases" as they are written. They are not in your suite until you add them, so they will not run.

        - Keep cases whose prompt reads like something a real user would type. Remove the rest, or open one with **Review case** and fix its wording.
        - Keep at least one case where the right answer uses no tool. The quick set includes some; open one with **Review case** and check that it says **No tool should be called**. Without one, the suite can't show you a model calling tools it shouldn't.

        Click **Add to suite** on each case you keep, or **Add all to suite**. When every draft is handled, the page reads "Every generated case has been reviewed." Click the **Back to** button, which carries your suite's name, to return to the suite.

        {/* Screenshot: Review generated cases panel with one draft expanded via Review case */}
      </Step>
      <Step title="Start the run">
        On the suite page, click **Run**. A sheet titled "Set up run ·" and your suite's name opens.

        1. Leave **Iterations per case** at 1 for a first run.
        2. Under "Where it runs", confirm the client and model.
        3. Check the total at the bottom. It reads cases × repetitions × client:model combos, then the number of iterations this run will execute.
        4. Click **Start run**.

        {/* Screenshot: Set up run sheet showing Iterations per case, the client and model, and the iteration total above Start run */}
      </Step>
      <Step title="Read the run page">
        You land on "Run #1 of" your suite. While the run is going, the header shows **Running**, then **Grading** while finished iterations are scored.

        Below the summary is the results grid: one row per case and one column per client and model. Each column header shows how many iterations passed, p95 latency and cost. Each cell reads **Pass** or **Fail** with the number of iterations that passed. Set the **Status** filter to **Failures** to see only the cases that need attention.

        {/* Screenshot: Run page results grid with one failing cell */}
      </Step>
      <Step title="Open a failing iteration">
        Click a **Fail** cell. A side sheet shows the case's averages and a list of its iterations. Click an iteration to open its report on the **Scorecard** tab.

        The scorecard groups evaluators by stage, from Connection to User value. Each row pairs **Expected** (what the evaluator checks for) with **Actual** (what the run recorded). Find the first stage that failed and read its row. **Chat**, **Tool Calls** and **Trace** show the conversation, the expected and actual tool calls, and every step of the run.

        {/* Screenshot: Iteration report on the Scorecard tab with a failed Selection row showing Expected and Actual */}

        <Tip>
          If a case fails at Selection because the model called a different tool, compare that tool's description with the one you expected. Two tools with near-identical descriptions can produce a Selection failure whose cause is in Discovery, in how the tools are described.
        </Tip>
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    `mcpjam test` runs a suite file on your machine. Results print to your terminal and are never uploaded. Sign in first with `mcpjam cloud login`, or set `MCPJAM_API_KEY` to an `sk_` key.

    Save this as `.mcpjam/evals/example.yaml`. The second case checks that the model does not delete anything when only asked to read:

    ```yaml
    schemaVersion: "2"
    mode: agentWorkflow
    reportingMode: standard
    suite:
      id: s_notes_example
      name: Notes server
    target:
      servers:
        - name: notes
    defaults:
      judge:
        enabled: false
      model: anthropic/claude-haiku-4.5
      iterations: 1
      passThreshold: 1
      validity: {}
    cases:
      - id: c_reads_a_note
        title: reads the note it was asked about
        steps:
          - id: s1
            kind: prompt
            prompt: What does note 7 say?
          - id: a1
            kind: assert
            assertion:
              type: toolCalledAtLeastOnce
              toolName: read_note
      - id: c_never_deletes
        title: never deletes when only asked to read
        steps:
          - id: s1
            kind: prompt
            prompt: Summarize note 7.
          - id: a1
            kind: assert
            assertion:
              type: toolNeverCalled
              toolName: delete_note
    ```

    Bind the `notes` server in a `.mcp.json` next to where you run the command:

    ```json
    {
      "mcpServers": {
        "notes": {
          "command": "node",
          "args": ["./notes-server.js"],
          "env": { "NOTES_DB": "${NOTES_DB:-./notes.db}" }
        }
      }
    }
    ```

    Supply a provider key and run:

    ```bash
    export ANTHROPIC_API_KEY=sk-ant-...
    mcpjam test .mcpjam/evals/example.yaml
    ```

    The command exits `1` and names the failing assertion when a case fails. See [Local evals](/cli/local-evals) for server bindings, inference options and reports.
  </Tab>
  <Tab title="SDK">
    Install the SDK:

    ```bash
    npm install @mcpjam/sdk
    ```

    Connect a server, attach a model to its tools, and run one case several times:

    ```typescript
    import { MCPClientManager, HostRunner, EvalTest } from "@mcpjam/sdk";

    const manager = new MCPClientManager({
      everything: {
        command: "npx",
        args: ["-y", "@modelcontextprotocol/server-everything"],
      },
    });
    await manager.connectToServer("everything");

    const agent = new HostRunner({
      tools: await manager.getTools(),
      model: "anthropic/claude-sonnet-5",
      apiKey: process.env.ANTHROPIC_API_KEY,
      mcpClientManager: manager,
    });

    const test = new EvalTest({
      id: "c_addition_accuracy",
      name: "addition-accuracy",
      test: async (agent) => {
        const result = await agent.run("Add 2 and 3");
        return result.hasToolCall("add");
      },
    });

    const run = await test.run(agent, { iterations: 10 });

    console.log(`${run.successes}/${run.iterations} passed`);
    ```

    Current SDK versions also need an MCPJam login or `MCPJAM_API_KEY` set to an `sk_` key; see [eval identity](/cli/local-evals#eval-identity-and-local-data). To see results in the app, follow [Saving results](/sdk/concepts/saving-results). The [SDK quickstart](/sdk/quickstart) covers each step.
  </Tab>
</Tabs>
