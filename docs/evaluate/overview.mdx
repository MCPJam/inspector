An eval sends a real prompt to a real model connected to your MCP server, records what the model does, and checks it: which tools it called, the arguments it passed, and whether the user's request was satisfied.

One scenario is a case. A suite groups cases and runs them against the clients and models you pick, so you see where each model gets your server right and where it doesn't.

<Note>
This section is for testing how models use your server. To call tools by hand, use the [Playground](/inspector/playground). To check your server against the MCP spec, use the [CLI conformance commands](/cli/overview#local-mcp-testing).
</Note>

## What an eval checks

MCPJam grades every iteration along six stages, in order, and reports the first stage that failed. That points at a likely owner: the connection, the server's tool catalog, the model's choice, or the server's answer.

| Stage | The question it answers |
|---|---|
| Connection | Could the client reach the server and start a session? |
| Discovery | Did the client receive usable tools and metadata? |
| Selection | Did the model choose the right tool for the request? |
| Tool call | Was the call made with usable arguments? |
| Response | Did the server return data the model could use? |
| User value | Was the user's actual request satisfied? |

[The user-value chain](/sdk/concepts/user-value-chain) lists which checks file at each stage.

## When to use evals

- Catch routing regressions: after you change a tool's description or input schema, rerun the suite. The run page counts cases regressed and fixed since the previous run.
- Compare models: run one suite across several client and model pairs. Results are broken out per pair, so a case that fails on only one model stands out.
- Gate releases: run a suite in CI and fail the build when it doesn't pass. See [Run evals in CI](/evaluate/run-evals-in-ci).

## Where to run evals

Pick the surface by where you want the suite to live.

<Tabs>
  <Tab title="Inspector">
    Click **Run** on the **Evaluate** tab. The suite lives in your MCPJam project. [Run your first eval](/evaluate/run-your-first-eval) creates one from a connected server and runs it.
  </Tab>
  <Tab title="CLI">
    Install the CLI and sign in. In CI, set `MCPJAM_API_KEY` to an `sk_` key instead of signing in.

    ```bash Install and sign in
    npm i -g @mcpjam/cli
    mcpjam cloud login
    ```

    `mcpjam test <file>` runs a suite file in your repository, such as `.mcpjam/evals/example.yaml`, on your machine. Results stay on your machine. See [Local evals](/cli/local-evals).

    ```bash Local run
    export ANTHROPIC_API_KEY=sk-ant-...
    mcpjam test .mcpjam/evals/example.yaml
    ```

    `mcpjam cloud eval run` runs a suite in your MCPJam project. `--file` uploads a suite file and runs it; its servers must be saved in the project. See [Evals in CI](/cli/ci#evals-in-ci).

    ```bash Hosted run
    # A suite saved in your project
    mcpjam cloud eval run --suite "Notes server" --wait

    # Or upload a suite file and run it
    mcpjam cloud eval run --file .mcpjam/evals/example.yaml --wait
    ```
  </Tab>
  <Tab title="SDK">
    `EvalTest` and `EvalSuite` from `@mcpjam/sdk` keep the suite in your test code. Results go to your project when you set `MCPJAM_API_KEY` and name a suite. See [Saving results](/sdk/concepts/saving-results).

    ```bash Install
    npm install @mcpjam/sdk
    ```

    ```ts evals/notes.mts
    import { EvalSuite, EvalTest, HostRunner, MCPClientManager } from "@mcpjam/sdk";

    const manager = new MCPClientManager({
      notes: { command: "node", args: ["./notes-server.js"] },
    });
    await manager.connectToServer("notes");

    const agent = new HostRunner({
      tools: await manager.getTools(),
      model: "anthropic/claude-haiku-4.5",
      apiKey: process.env.ANTHROPIC_API_KEY,
      mcpClientManager: manager,
    });

    const suite = new EvalSuite({ name: "Notes server" });
    suite.add(new EvalTest({
      id: "c_reads_a_note",
      name: "reads the note it was asked about",
      test: async (a) => (await a.run("What does note 7 say?")).hasToolCall("read_note"),
    }));

    await suite.run(agent, { iterations: 3 });
    console.log(`Accuracy: ${(suite.accuracy() * 100).toFixed(1)}%`);
    await manager.disconnectServer("notes");
    ```

    ```bash Run
    export ANTHROPIC_API_KEY=sk-ant-...
    npx tsx evals/notes.mts
    ```
  </Tab>
</Tabs>

Suites created from a suite file or the SDK carry a **CI** badge in the app; change them in code, not in the app.

<Info>
  Current CLI and SDK versions need an MCPJam login or an `sk_` API key for every eval, including runs on your own provider key. See [eval identity](/cli/local-evals#eval-identity-and-local-data).
</Info>

<Warning>
Evals call real models. Each iteration spends MCPJam credits when MCPJam serves the model, or tokens on your provider account when you bring your own key. A run's size is cases × iterations per case × client/model pairs; the Inspector's run sheet shows that total before you start.
</Warning>
