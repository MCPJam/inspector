An eval run sends real prompts to a real model, and the model calls tools on your real servers with the credentials saved for them. This page lists what a run can reach and what leaves MCPJam while it runs and is graded.

## Servers and their auth

A run connects each client's server group (see [Run a suite](/evaluate/run-a-suite#what-a-run-needs)) and uses the auth saved on each HTTP server:

| Server auth | What the run sends |
|---|---|
| Stored bearer token | The token, on every request to that server. |
| Stored headers | The headers saved on the server. |
| OAuth | An OAuth access token for that server, added as a Bearer header when the run starts. |

Header overrides set on a client are not applied to eval runs. Hosted runs can't start STDIO servers; run those on your machine with [`mcpjam test`](/cli/local-evals), which reads `command`, `args` and `env` from your MCP config.

<Warning>
  Evals call your real server. A case that asks the model to delete a record can delete it, and an iteration count of 5 asks five times. Point suites at a staging server, or give the server read-only credentials, before you add cases that change data.
</Warning>

## Model access

Each iteration calls the model you picked, paid for in one of two ways:

| Model | Who pays for the tokens | Cost on the results page |
|---|---|---|
| A model MCPJam provides | Your organization's MCPJam credits. | The MCPJam-billed cost. |
| A model from your own provider key (BYOK) | Your provider, on your account. | A dash: MCPJam billed nothing, so there is no cost to show. |

When your organization runs out of MCPJam credits, a run whose models all use credits can't start; switch at least one to a model from your own provider. On Enterprise plans an admin can make AI features run only on the organization's own providers, and then the model list offers only those.

Every iteration also counts against your organization's eval iteration allowance, whichever model it uses.

## What leaves MCPJam

| Recipient | What it receives | When |
|---|---|---|
| The provider of each model you run | The case's prompts, your server's tool definitions, and the tool results the model reads. | Every iteration. |
| The goal completion judge's model provider, through OpenRouter | The recorded conversation, the trace, the available tool definitions, runtime context, and supported inline media. Credentials are redacted. | Each completed iteration, while the judge is on. It is on and automatic by default, with `openai/gpt-5.4-mini`. |
| TypeSafe AI's Jev classifier, through Vercel AI Gateway | For rubric checks: the request, the expected outcome, the final answer, and a clipped trajectory. Credentials are redacted. If Jev can't be reached, the same questions go to a fallback model through Vercel AI Gateway or OpenRouter. | Each iteration the goal completion judge grades, when the suite has grading criteria or rubric-check questions. |

## Turn grading off

<Steps>
  <Step title="Open the suite's settings">
    On the suite page, click **Suite settings**.
  </Step>
  <Step title="Clear the judge rows">
    Under **Evaluators**, clear **Goal completion judge**. Rubric checks run on the iterations that judge grades, so they stop too. To keep the judge and stop only rubric checks, clear **Rubric checks** instead.
  </Step>
  <Step title="Save">
    Click **Save settings**. The change applies to future runs.
  </Step>
</Steps>

To keep the judge on for the suite but skip it for one case, turn on **Skip the judge for this case** in the case editor and save the case.
